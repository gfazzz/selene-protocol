## Диспетчерская, сол 2, 01:10

Табло над пультом — три ряда подписей, по одной на пакет. Тамура стоит у двери,
щурится и не может разобрать ни одной.

— Я отсюда должен видеть, где кислород, а где давление, — говорит он. — А вижу
кашу.

Каша выглядит так:

```
0214 o2 20.900000000000002 #118
0042 P 101.3 #7
3000 CO2 0.4 #12011
```

Подписи собирает скрипт Рейеса, одной строкой:

```python
label = node + " " + sensor + " " + str(value) + " #" + str(sequence)
```

Склейка через `+` кладёт куски вплотную, сколько бы символов в них ни было. Поэтому
столбцы разъезжаются. Код датчика приходит то заглавными, то строчными: прошивки на
узлах разные. А `str(value)` показывает число так, как оно лежит в памяти, со всеми
двоичными хвостами: `0.1 + 20.8` даёт `20.900000000000002`, и табло честно
выводит все пятнадцать знаков.

— Сделай так, чтобы читалось с другого конца зала, — говорит Тамура и уходит на
обход шлюзов.

В сыром потоке, между пакетами 46 и 48, приходит строка:

```
0000;:<6 И :>8.2F;0.00;47;0
```

По формату это пакет: пять полей, точки с запятой на месте. В поле датчика —
что-то, похожее на описание столбцов. Вернувшись, Тамура смотрит в поток через твоё
плечо: «Опять узел из ниоткуда. Справочник когда-нибудь починят».

> **SELENE — не декорация.** В сюжете она пока только пакеты с узла, которого нет. В реальности это **чат твоего редактора**: всё, что она «говорит», можно спросить по-настоящему. Только режим `Ask`, а не `Agent`: она объясняет, работу делаешь ты.

## Теория: строки, методы и форматирование

### Методы строки возвращают новую строку

В s01e01 выяснилось, что строку нельзя изменить. Поэтому любой метод строки
возвращает **новую** строку, а исходная остаётся какой была:

```python
>>> code = "  co2 "
>>> code.strip()
'co2'
>>> code.upper()
'  CO2 '
>>> code.strip().upper()
'CO2'
>>> code
'  co2 '
```

Методы можно выстраивать цепочкой: каждый следующий работает с результатом
предыдущего. Ещё несколько, которые понадобятся в сезоне:

```python
>>> "0000;SELENE".startswith("0000")
True
>>> "0214;O2;20.90".split(";")
['0214', 'O2', '20.90']
>>> ", ".join(["O2", "P", "CO2"])
'O2, P, CO2'
```

`join` устроен наоборот, чем ожидаешь: метод вызывают у **разделителя**, а куски
передают ему. Разделитель встаёт только между кусками, поэтому лишней запятой в
конце не бывает. Квадратные скобки — это список: подробно они в s01e05, а пока это
просто способ передать несколько строк разом.

### f-строка вместо склейки

Буква `f` перед кавычкой разрешает вставлять в строку значения в фигурных скобках:

```python
>>> node = "0214"
>>> value = 20.9
>>> f"узел {node}: {value}"
'узел 0214: 20.9'
```

Внутри скобок — любое выражение Python. Числа не нужно оборачивать в `str()`: f-строка
сделает это сама.

### Ширина, выравнивание, точность

После двоеточия внутри скобок идёт **спецификация формата**:

```python
>>> f"[{'O2':<6}]"
'[O2    ]'
>>> f"[{'O2':>6}]"
'[    O2]'
>>> f"[{20.9:8.2f}]"
'[   20.90]'
>>> f"[{118:06d}]"
'[000118]'
```

`<` и `>` — левый и правый край, число — **минимальная** ширина поля, `.2f` — два
знака после точки, `06d` — целое шириной 6 с ведущими нулями. Числа по умолчанию
прижимаются вправо, строки — влево. Ширина — минимум, а не потолок: длинное
значение выйдет целиком и раздвинет столбец. Обрезать молча было бы хуже: номер
`1234567`, превратившийся в `123456`, — уже номер чужого пакета.

### `!r`: показать, что там на самом деле

```python
>>> raw = "9,6\n"
>>> f"поле value: {raw}"
'поле value: 9,6\n'
>>> f"поле value: {raw!r}"
"поле value: '9,6\\n'"
```

`!r` вставляет не само значение, а его **представление**: со всеми кавычками,
пробелами и невидимыми символами, как в интерпретаторе. Для журнала разбора это
единственный честный способ показать сырое поле: пробел в конце или перевод строки
иначе не увидеть.

## Проверка: SELENE задаёт вопросы

```
[КАНАЛ 0 · УЗЕЛ НЕ УКАЗАН]
ВЫРАВНИВАНИЕ — НЕ УКРАШЕНИЕ. ЭТО СПОСОБ НЕ ПЕРЕПУТАТЬ СТОЛБЦЫ В ЧЕТЫРЕ УТРА.
ТРИ ВОПРОСА.
```

**1.** «`code.strip()` и `code.upper()` двумя отдельными строками. Что окажется в `code`?»

<details><summary>Ответ</summary>

То же, что было. Оба метода вернули новые строки, и ни одну из них никто не взял.
Чтобы получить и то и другое, вызовы выстраивают цепочкой: `code.strip().upper()`.
</details>

**2.** «`f"{20.9:8.2f}"` и `str(round(20.9, 2))`. Что из этого годится для столбца?»

<details><summary>Ответ</summary>

Только первое. `round` даёт `20.9`, и `str` покажет `'20.9'`: один знак после
точки, ширина четыре символа. Столбец разъедется на первом же `101.3`. Спецификация
формата задаёт и ширину, и число знаков, и выравнивание сразу.
</details>

**3.** «В журнале записано `поле node: 0214`. Почему по такой записи не понять, что
было в поле?»

<details><summary>Ответ</summary>

Потому что пробел в конце, табуляция и перевод строки не видны. `!r` покажет
`'0214 '` в кавычках, и лишний пробел станет очевиден.
</details>

## Разбор типичных ошибок

1. **Склейка через `+` и `str()`.** Ширина каждого куска случайна, столбцы
   разъезжаются, у `float` вылезают двоичные хвосты. Ошибка Рейеса.
2. **`round` вместо точности.** Число округлится, но `20.9` останется `20.9`, а не
   `20.90`, и ширина поля не появится.
3. **Метод отдельной строкой.** `code.strip()` без присваивания ничего не меняет.
4. **`replace(" ", "")` вместо `strip()`.** Убирает и пробелы внутри кода.
5. **`",".join` без пробела или ручная склейка с запятой в конце.** Разделитель
   встаёт ровно между кусками, и только `join` гарантирует это без лишних условий.
6. **Кавычки вручную вместо `!r`.** `f"'{raw}'"` не покажет перевод строки, а у
   строки с апострофом кавычки окажутся неверными.
