# Теория — s01e02

## 1. Строка — последовательность символов

Строка в Python — неизменяемая последовательность символов Юникода. У неё есть
длина, её можно проверить на вхождение и взять символ по номеру:

```python
>>> code = "CO2"
>>> len(code)
3
>>> "O" in code
True
>>> code[0]
'C'
```

Номера начинаются с нуля; индексы подробно — в s01e03. Вырезать кусок строки умеют срезы,
но это предмет s02e01.

Символ — не байт. `len("ё")` равно 1, хотя в UTF-8 эта буква занимает два байта.
Как строка превращается в байты и обратно, разбирается в S3.

> отчёт, вырезая буквы из газеты: возможно, но столбцы потом не сходятся».*

## 2. Почему методы возвращают новую строку

Из неизменяемости строки (s01e01, §3) следует простое правило: метод строки не может
её изменить и потому возвращает новую. У этого правила два следствия.

**Цепочки работают.** `raw.strip().upper()` — сначала новая строка без краёв, потом
новая строка заглавными. Порядок иногда важен: `" o2 ".upper().strip()` даёт то же
самое, а вот `split` после `upper` и до него дают разные куски, если разделитель
— буква.

**Забытый результат пропадает.** Вызов `code.strip()` отдельной строкой выполняется,
создаёт новую строку и тут же её теряет. Ошибки нет, и поэтому эту ошибку не видно.

## 3. Методы, которые понадобятся в сезоне

| Метод | Что делает | Пример |
|---|---|---|
| `strip()` | убирает пробельные символы по краям | `" O2\n".strip()` → `'O2'` |
| `upper()`, `lower()` | регистр | `"o2".upper()` → `'O2'` |
| `startswith(s)` | начинается ли строка с `s` | `"0000;X".startswith("0000")` → `True` |
| `split(sep)` | режет по разделителю | `"a;b".split(";")` → `['a', 'b']` |
| `join(parts)` | склеивает куски разделителем | `"-".join(["a", "b"])` → `'a-b'` |
| `replace(a, b)` | заменяет все вхождения | `"9,6".replace(",", ".")` → `'9.6'` |

`strip()` без аргумента убирает не только пробелы, но и табуляцию, перевод строки и
другие пробельные символы. С аргументом — только перечисленные символы:
`"##O2##".strip("#")` даёт `'O2'`.

Регистр устроен сложнее, чем кажется: `"ß".upper()` — это `'SS'`, две буквы вместо
одной. Для сравнения без учёта регистра есть `casefold()`: `"Straße".casefold()`
даёт `'strasse'`. На табло колонии немецких кодов нет, но длина строки после `upper`
в общем случае может измениться, и это стоит помнить.

## 4. `join`: метод разделителя

Почему `", ".join(codes)`, а не `codes.join(", ")`? Потому что склеивать можно что
угодно, что отдаёт строки по одной: список, кортеж, результат `split`. Делать `join`
методом каждого такого типа пришлось бы много раз, а у разделителя он один.

Склейка в цикле `result = result + code + ", "` даёт лишний разделитель в конце, и
его приходится отрезать. `join` ставит разделитель только между кусками, и проблемы
нет. Кроме того, склейка в цикле создаёт новую строку на каждом шаге (строки
неизменяемы), а `join` собирает результат один раз.

## 5. Три способа форматировать

У Python три способа вставить значения в строку, и все они встречаются в чужом коде:

```python
>>> "%s %.2f" % ("O2", 20.9)
'O2 20.90'
>>> "{} {:.2f}".format("O2", 20.9)
'O2 20.90'
>>> f"{'O2'} {20.9:.2f}"
'O2 20.90'
```

Оператор `%` пришёл из C и самый старый. Метод `format` появился в Python 2.6.
f-строки — в Python 3.6 (PEP 498). Спецификация формата после двоеточия у `format` и
у f-строк одна и та же. В коде курса — только f-строки: значение стоит прямо там,
где оно выводится, и его не нужно сопоставлять с позицией в списке аргументов.

## 6. Мини-язык спецификации формата

Полная форма спецификации: `[[заполнитель]выравнивание][знак][0][ширина][,][.точность][тип]`.

| Спецификация | Значение | Результат |
|---|---|---|
| `<6` | строка, левый край, ширина 6 | `'O2    '` |
| `>6` | правый край | `'    O2'` |
| `^6` | по центру | `'  O2  '` |
| `*>6` | заполнитель `*` | `'****O2'` |
| `8.2f` | ширина 8, два знака | `'   20.90'` |
| `08.2f` | то же с нулями | `'00020.90'` |
| `06d` | целое с нулями | `'000118'` |
| `,.2f` | разделитель тысяч | `'1,234,567.89'` |

Тип должен подходить значению: `f"{'x':d}"` и `f"{20.9:06d}"` поднимают `ValueError`.
Это полезно: формат для целого не примет дробное молча.

Ширина — **минимальная**. Длинное значение займёт столько места, сколько нужно. Если
столбец обязан быть ровно шесть символов, длинное значение придётся обрезать явно,
и это отдельное решение: на табло диспетчерской обрезанный номер пакета опаснее
кривого столбца.

## 7. `str` и `repr`

У каждого значения два строковых вида:

```python
>>> print(str("x"), repr("x"))
x 'x'
>>> str(0.1 + 0.2), repr(0.1 + 0.2)
('0.30000000000000004', '0.30000000000000004')
```

`str` — для человека, `repr` — для программиста: представление, по которому видно, что
это за значение. Для строки `repr` добавляет кавычки и показывает невидимые символы
как `\n` и `\t`. Если внутри есть апостроф, кавычки меняются на двойные:
`repr("it's")` даёт `"it's"`.

В f-строке `!r` вызывает `repr`, `!s` — `str` (он и так по умолчанию). Ещё одна
удобная форма для отладки — `=`: `f"{x=}"` даёт `'x=3'`, имя и значение сразу.

Интерпретатор, выводя результат выражения, показывает именно `repr`. Поэтому в
примерах этой серии строки видны в кавычках.

## 8. Компромисс: формат в одном месте

Подпись пакета собирается в одной функции, а не в каждом месте, где её выводят. Это не
вопрос вкуса. Если формат записан один раз, его меняют один раз: ширину столбца
датчиков, число знаков, вид номера. Если он размазан по скрипту, как у Рейеса, каждое
изменение — это поиск всех склеек и надежда, что нашлись все.

По той же причине `format_reading` зовёт `normalize_code`, а не повторяет
`strip().upper()`: правило приведения кода тоже должно жить в одном месте.
