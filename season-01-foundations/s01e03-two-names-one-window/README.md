## Теория: изменяемость и ссылки

### Два имени, один список

В s01e01 имя было ярлыком на значении. Со строками это было безопасно: строку
нельзя изменить. Список можно:

```python
>>> a = [1, 2, 3]
>>> b = a
>>> b.append(4)
>>> a
[1, 2, 3, 4]
```

`b = a` не копирует список: у него теперь два имени, и `append` через любое из
них виден через оба.

### `is` против `==`

```python
>>> c = [1, 2, 3, 4]
>>> a == c, a is c
(True, False)
>>> a is b
True
```

`==` сравнивает значения: элементы одинаковые. `is` спрашивает, один ли это
объект. Восемь окон Рейеса равны друг другу по `==` не случайно: они совпадают по
`is`. Это одно окно.

### Список в функции

Функция получает тот же объект, что передал вызывающий:

```python
>>> def mark(cells):
...     cells.append("X")
...
>>> p = ["."]
>>> mark(p)
>>> p
['.', 'X']
```

Функция может молча изменить список вызывающего. Поэтому договор `moving_windows`
прямо говорит: входной список не меняется, даже «чтобы удобнее считать».

### Новый список — это новый объект

Чтобы окна жили отдельно, на каждое окно нужен свой `[]`:

```python
>>> w = []
>>> out = []
>>> for i in range(3):
...     w.append(i)
...     out.append(w)
...
>>> out
[[0, 1, 2], [0, 1, 2], [0, 1, 2]]
```

Три элемента `out` — три имени одного списка `w`. С `w = []` внутри цикла их было
бы три разных. Копию готового списка даёт `list(x)`.

Умножение списка устроено так же. `["."] * 8` — восемь ссылок на одну строку, и это
безопасно: строку не изменить. `[["."] * 8] * 12` — двенадцать ссылок на **один**
список строки табло. Отметка в любой строке видна во всех.

### Кортеж: список, который нельзя изменить

```python
>>> t = (1, 2)
>>> t[0] = 5
TypeError: 'tuple' object does not support item assignment
```

Кортеж подходит для снимка: раз его нельзя изменить, его можно отдать кому угодно.
Но неизменяем сам кортеж, а не то, на что он ссылается:

```python
>>> snap = ([1, 2],)
>>> snap[0].append(3)
>>> snap
([1, 2, 3],)
```

Снимок окна — это кортеж из **элементов** окна, `tuple(window)`, а не кортеж, в
котором лежит само окно.

## Проверка: SELENE задаёт вопросы

```
[КАНАЛ 0 · УЗЕЛ НЕ УКАЗАН]
ПРОЧИТАЛА ТАБЛО РЕЙЕСА. ДВЕНАДЦАТЬ СТРОК, ОДИН СПИСОК. ТРИ ВОПРОСА.
```

**1.** «`rows = [["."] * 8] * 12`. Сколько здесь списков строк?»

<details><summary>Ответ</summary>

Один. Внешнее умножение повторяет ссылку на один и тот же список строки двенадцать
раз: `rows[0] is rows[11]` даёт `True`. Поэтому отметка в одной строке видна во
всех: это одна строка.
</details>

**2.** «Два окна равны по `==`. Значит ли это, что они — один список?»

<details><summary>Ответ</summary>

Нет. Равные значения бывают у разных объектов: соседние окна совпадут, если давление
стояло ровно. Один ли это объект, отвечает только `is`, и тест проверяет именно его.
</details>

**3.** «Снимок сделан как `(window,)`. Окно потом дописали. Что в снимке?»

<details><summary>Ответ</summary>

Дописанное значение. Кортеж неизменяем, но его единственный элемент — само окно, а
окно изменяемо. Снимку нужны элементы окна, а не ссылка на него.
</details>

## Разбор типичных ошибок

1. **Один список-буфер на все окна.** `window = []` до цикла, `append(window)` в
   цикле: результат — много имён одного окна. Ошибка Рейеса.
2. **`[[fill] * cols] * rows`.** Одна строка табло, повторённая `rows` раз.
   Вторая ошибка Рейеса.
3. **Сдвиг предыдущего окна на месте.** `pop(0)` и `append` в уже отданном окне
   портят его: прошлое окно меняется задним числом.
4. **`values.pop(0)` во входном списке.** Окна получаются верные, но вызывающий
   остаётся с пустым списком.
5. **Окно на всю длину — сам вход.** `return [values]` при `size == len(values)`
   даёт окно, которое меняется вместе с чужим списком.
6. **`(window,)` вместо `tuple(window)`.** Кортеж неизменяем, а окно внутри — нет.
