# Теория — s01e03

## 1. Изменяемые и неизменяемые

В s01e01 у каждого объекта было тождество, тип и значение. Тип решает ещё одно:
**можно ли изменить значение, не меняя тождества.**

| Неизменяемые | Изменяемые |
|---|---|
| `int`, `float`, `bool`, `str`, `tuple` | `list` (а дальше — `dict` и `set`) |

С неизменяемым объектом два имени ничем не грозят:

```python
>>> x = 5
>>> y = x
>>> y += 1
>>> x, y
(5, 6)
```

`y += 1` не меняет пятёрку: он создаёт шестёрку и перевешивает ярлык `y`. Со
списком `+=` ведёт себя иначе, и это первая настоящая ловушка серии.

## 2. `+=` и `=` для списка

```python
>>> a = [1]
>>> b = a
>>> a += [5]
>>> b
[1, 5]
>>> a = a + [6]
>>> b, a
([1, 5], [1, 5, 6])
```

Для списка `a += [5]` дописывает в **тот же** объект, и `b` это видит. А `a = a + [6]`
строит новый список и перевешивает `a`, оставляя `b` на старом. Две строчки,
которые выглядят как одна, делают разные вещи. Правило: `+=`, `append`, `pop`,
присваивание элемента `a[0] = …` меняют объект; `=` перевешивает имя.

> *SELENE, в отладочном канале: «Рейес писал `+=` и думал, что копирует. Это
> заблуждение разделяют многие. Регламент колонии тоже копирует ответственность
> через `+=`».*

## 3. Почему Python передаёт ссылки

Python никогда не копирует объект неявно: ни при присваивании, ни при передаче в
функцию, ни при добавлении в список. Это решение принято ради скорости и
предсказуемости. Копирование списка в миллион элементов при каждом вызове функции
стоило бы дорого, а правило «объект не копируется никогда» проще, чем «иногда».

Поэтому говорят, что Python передаёт аргументы «по ссылке на объект»: функция
получает тот же объект. Изменить его она может, а перевесить имя вызывающего — нет:

```python
>>> def replace(cells):
...     cells = ["new"]
...
>>> p = ["old"]
>>> replace(p)
>>> p
['old']
```

Внутри функции `cells = …` перевесил только местный ярлык. А `cells.append(…)`
изменил бы общий объект.

## 4. `is`, `==` и `id`

`a is b` истинно, когда `id(a) == id(b)`: это один объект. `==` спрашивает сам
объект, равен ли он другому; для списков это поэлементное сравнение.

```python
>>> [1, 2] == [1, 2]
True
>>> [1, 2] is [1, 2]
False
```

`is` нужен редко: для проверки на `None` (s01e02) и для вопроса «это один объект?».
Сравнивать через `is` числа и строки нельзя: результат зависит от того, решил ли
интерпретатор переиспользовать объект, и может разойтись между версиями Python.

## 5. Умножение и вложенность

`[x] * n` даёт список из `n` ссылок на **один** объект `x`. Пока `x` неизменяем,
это незаметно: `["."] * 8` безопасно. Когда `x` — список, каждая «строка» оказывается
одной и той же:

```python
>>> rows = [["."] * 3] * 2
>>> rows[0][1] = "X"
>>> rows
[['.', 'X', '.'], ['.', 'X', '.']]
>>> rows[0] is rows[1]
True
```

Эта ошибка настолько частая, что ей отведён отдельный вопрос в официальном FAQ
Python. Лечится она только одним способом: создавать каждую строку заново.

## 6. Поверхностная копия

`list(x)` создаёт новый внешний список, но элементы в нём — те же объекты:

```python
>>> grid = [[0], [0]]
>>> copy = list(grid)
>>> copy is grid, copy[0] is grid[0]
(False, True)
```

Для окна из чисел этого достаточно: числа неизменяемы. Для табло из списков —
нет: копия внешнего списка делит строки с оригиналом. Глубокое копирование
существует, но в стандартной библиотеке оно лежит в модуле `copy`, а модули и
импорт — тема s01e06. Сегодня проще и честнее не делить объекты с самого начала.

## 7. Кортеж

Кортеж — упорядоченная последовательность, которую нельзя изменить: ни присвоить
элемент, ни дописать, ни удалить. Отсюда два свойства.

**Кортеж можно хешировать**, если хешируются его элементы:

```python
>>> hash([1, 2])
TypeError: unhashable type: 'list'
```

`hash((1, 2))` работает. Это понадобится в s01e04: ключом словаря может быть кортеж,
но не список.

**Кортеж безопасно отдавать.** Снимок окна, отданный в отчёт, не изменится у
получателя под ногами. Если, конечно, внутри кортежа не лежат изменяемые объекты.

## 8. Знаменитая ловушка: `+=` внутри кортежа

```python
>>> t = (1, [2])
>>> t[1] += [3]
TypeError: 'tuple' object does not support item assignment
>>> t
(1, [2, 3])
```

Ошибка есть, и изменение тоже есть. `t[1] += [3]` выполняется в два шага: сначала
список внутри дописывается на месте (это удаётся), потом результат присваивается
элементу кортежа (это запрещено). Ramalho разбирает этот пример в «Fluent Python»
(гл. 2) как урок: не клади изменяемое в неизменяемое и не рассчитывай, что кортеж
его защитит.

## 9. Компромисс: копировать или делить

Делить объекты дёшево: ни памяти, ни времени на копию. Копировать безопасно: никто
не испортит твой результат. Хорошее правило для функций курса:

- **вход не меняй**, если договор не говорит обратного;
- **результат создавай новым**, чтобы вызывающий мог делать с ним что угодно;
- **неизменяемое возвращай**, когда результат должен оставаться таким, каким был
  отдан.

`list.append` возвращает `None`, а не список. Это сделано нарочно: метод, который
меняет объект, не притворяется функцией, которая создаёт новый. В s01e05 это
соглашение встретится снова.
