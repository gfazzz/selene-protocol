# Теория — s01e04

## 1. Распаковка — это присваивание

`node, value = pair` — не особый синтаксис для кортежей, а общее правило: слева
может стоять несколько имён, справа — любая последовательность той же длины.

```python
>>> a, b = "xy"
>>> a, b
('x', 'y')
>>> node, sensor = ["0214", "O2"]
```

Скобки вокруг кортежа справа не нужны: `a, b = 1, 2` — это кортеж `(1, 2)`,
разложенный по двум именам. Отсюда и обмен без временной переменной:

```python
>>> a, b = 1, 2
>>> a, b = b, a
>>> a, b
(2, 1)
```

Правая часть вычисляется целиком до того, как что-то присвоено, поэтому значения
не затирают друг друга.

> служебной записки. Python об этом регламенте не знает».*

## 2. Звёздочка

Одно имя может быть со звёздочкой: оно собирает всё, что не досталось остальным,
и всегда становится **списком**, даже пустым.

```python
>>> first, *rest = [1, 2, 3]
>>> rest
[2, 3]
>>> *head, last = [1, 2, 3]
>>> head
[1, 2]
>>> first, *rest = [1]
>>> rest
[]
```

Звёздочки две быть не может: Python не знает, как поделить середину. Это удобный
способ отделить «узел» от «остального пакета», когда остальное ещё не нужно
разбирать.

## 3. Распаковка в цикле

`for index, value in enumerate(items)` — та же распаковка, но на каждом шаге: цикл
берёт очередную пару и раскладывает её по двум именам. Работает с любыми парами:

```python
>>> for node, value in [("0042", 101.5), ("1187", 95.8)]:
...     print(node, value)
...
0042 101.5
1187 95.8
```

Распаковка бывает и вложенной: `for number, (node, value) in enumerate(pairs)` —
внешняя пара «номер, пара», внутренняя — «узел, значение».

## 4. Как устроена сортировка

Python сортирует алгоритмом, который Тим Питерс написал для CPython в 2002 году
(Timsort; с 3.11 в его слиянии используется вариант Powersort). Для курса важны
два его свойства.

**Устойчивость гарантирована документацией.** Элементы с равным ключом сохраняют
исходный порядок, и это часть контракта языка, а не случайность реализации. Флаг
`reverse=True` устойчивость не ломает: равные элементы всё равно идут в порядке
входа. А вот `reversed(sorted(...))` ломает: он разворачивает и равные тоже.

**Быстрота на почти упорядоченных данных.** Поток телеметрии почти всегда приходит
почти по порядку, и алгоритм находит уже упорядоченные куски и сливает их.

Из устойчивости следует приём: сортировка по нескольким ключам в несколько
проходов, **начиная с младшего**. Сначала по узлу, потом по значению — и при равном
значении узлы окажутся по порядку.

```python
>>> rows = [("2210", 104.5), ("0042", 104.5), ("1187", 99.0)]
>>> by_node = sorted(rows, key=lambda row: row[0])
>>> sorted(by_node, key=lambda row: row[1], reverse=True)
[('0042', 104.5), ('2210', 104.5), ('1187', 99.0)]
```

## 5. Ключ и сравнение кортежей

Без `key` Python сравнивает элементы целиком. Кортежи сравниваются поэлементно,
слева направо, до первого различия. Это удобно и коварно: ключом становится всё,
что лежит в кортеже, включая то, что ты не собирался делать ключом.

Скрипт Рейеса сортировал пары `(значение, узел)`. Строки сравниваются посимвольно,
по кодам символов: `"2210" > "0042"`, потому что `"2" > "0"`. Время прихода в паре
вообще не лежало, поэтому учесть его было нельзя.

`key` вызывается **один раз** на каждый элемент, а не на каждое сравнение. Поэтому
дорогой ключ не делает сортировку медленной в разы.

`lambda reading: reading[2]` — функция без имени, записанная прямо на месте. Она
ничем не лучше обычной `def`, просто короче. Устройство функций — в s01e08.

## 6. `zip` и молчание

`zip` проектировался для последовательностей одной длины и долго молча обрезал по
самой короткой. Это поведение по умолчанию сохраняется, потому что на нём держится
много старого кода. Параметр `strict=True` появился в Python 3.10
([PEP 618](https://peps.python.org/pep-0618/)) именно из-за ошибок вроде той, что
сделал Рейес.

Обрезание бывает и полезным: `zip(values, values[1:])` даёт соседние пары (срез
`values[1:]` — «всё, кроме первого»; срезы разберём в s02e01). Это
осознанный выбор, и короче второй список ровно на один элемент. Если же длины
обязаны совпадать, молчание — ошибка, и `strict=True` превращает её в
`ValueError` в том месте, где она случилась, а не в пустую строку в отчёте.

## 7. `enumerate` вместо счётчика

```python
number = 1
for reading in readings:
    lines.append(str(number) + " " + reading[0])
    number = number + 1
```

Ручной счётчик — третья вещь, которую надо помнить: начать с нужного, увеличить в
конце каждого шага, не забыть при раннем `continue`. `enumerate(readings, start=1)`
делает то же самое и не забывает.

## 8. `min`, `max`, `sum` и пустота

| Функция | Пустой вход | При равенстве |
|---|---|---|
| `min`, `max` | `ValueError`, если не задан `default` | первый из равных |
| `sum` | `0` (или `start`) | — |
| `sorted` | `[]` | порядок входа |

`min(stream, key=value_of, default=None)` вернёт `None` на пустом потоке. В задании
пустоту проверяют явно: результат `extremes` — пара, и `None` вместо пары честнее,
чем пара из двух `None`.

`sum` складывает по порядку, и для чисел с плавающей точкой порядок влияет на
последние знаки. К этому вернёмся в S4.

## 9. Компромисс: вернуть новое или изменить вход

`sorted` и `list.sort()` существуют вместе не случайно. Сортировка на месте не
тратит память на копию, и для большого списка, который больше никому не нужен, это
правильный выбор. Но функция, получившая список от вызывающего, не знает, нужен ли
он ему ещё. Поэтому правило курса простое: **функция не меняет того, что ей дали,
если это не её прямая работа.** Цена — одна копия.
