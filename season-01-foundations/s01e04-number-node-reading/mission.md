## Обстановка

Утренний отчёт ставит узлы с равным давлением не в том порядке, в каком они
перевалили за предел, а склейка двух выгрузок молча теряет хвост. Оба списка
отчёта надо собрать заново, встроенными функциями и без молчаливых потерь.

## Приказ

Написать `artifacts/toolkit/walk.py`: четыре функции обхода потока пакетов.

## Данные

Пакет — кортеж из `parse_reading` (s01e01):

```python
("0042", "P", 104.5, 1206, False)   # узел, датчик, значение, номер, тревога
```

Номер — сквозной номер пакета в потоке смены: чем меньше, тем раньше пришёл.
Функция `value_of(reading)` уже есть в каркасе и возвращает значение.

## Договор вызова

```python
worst(readings, 5)            # → 5 пакетов с наибольшим значением, по убыванию
numbered(readings)            # → [(1, пакет), (2, пакет), ...]
numbered(readings, start=0)   # → [(0, пакет), ...]
pair_up(nodes, values)        # → [(узел, значение), ...]
extremes(readings)            # → (наименьший пакет, наибольший пакет) или None
```

## Критерии приёмки

- [ ] `worst` возвращает пакеты по убыванию значения; ни один пакет за бортом не
      больше отобранных.
- [ ] При равных значениях `worst` сохраняет порядок прихода, в том числе на
      границе отбора.
- [ ] `worst` не меняет входной список и всегда возвращает новый.
- [ ] `worst(..., 0)` — пустой список; `n` больше длины — все пакеты.
- [ ] `numbered` нумерует подряд с `start` (по умолчанию с 1) и отдаёт сами пакеты.
- [ ] `pair_up` склеивает узлы и значения в пары, а при разной длине поднимает
      `ValueError`.
- [ ] `extremes` возвращает `None` для пустого потока и при равенстве берёт пакет,
      пришедший первым; наибольший совпадает с первым из `worst`.
- [ ] `extremes` не меняет входной список.
- [ ] `make test` → 45 зелёных проверок.
