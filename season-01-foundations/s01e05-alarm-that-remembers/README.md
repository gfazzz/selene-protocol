Узел 0042, жилой модуль у самого кратера. Тамура хмурится.

— Две тревоги. Давление девяносто один. — Он уже тянется к бланку наряда. — Это
жилой отсек. Поднимаю ремонтную бригаду.

Ты смотришь в сводку через его плечо. Номера пакетов: 40 и 42. Пакеты 0042 идут
сегодня под номерами 1206 и 1219, а 40 и 42 пришли в начале смены от 2210. В
сводке по 0042 стоят тревоги **другого узла**.

— Перезапусти сводку, — говорит Тамура, не отрываясь от бланка. — У Рейеса так
бывало. Перезапустишь — и всё проходит.

Ты открываешь функцию:

```python
def collect_alerts(readings, low, high, found=[]):
    for reading in readings:
        node, sensor, value, sequence, alarm = reading
        if alarm or value < low or value > high:
            found.append(reading)
    return found
```

И проверяешь в интерпретаторе: вызов для 2210, затем для 0042, у которого всё в
норме.

```python
>>> collect_alerts(node_2210, 96, 104)
[('2210', 'P', 91.2, 40, False), ('2210', 'P', 100.1, 42, True)]
>>> collect_alerts(node_0042, 96, 104)
[('2210', 'P', 91.2, 40, False), ('2210', 'P', 100.1, 42, True)]
```

Второй вызов ничего не нашёл и вернул находки первого. Перезапуск помогал Рейесу
по простой причине: новый запуск программы — новый список. Ошибка жила между
вызовами, а не внутри одного.

В поле примечания ты пишешь: `почему функция помнит?` Ответ приходит раньше, чем

## Теория: функции и значения по умолчанию

### Функция — тоже значение

До сих пор `def` был приёмом записи из каркаса. Теперь по существу. `def` —
обычная инструкция: Python выполняет её, создаёт объект-функцию и привязывает к
нему имя, как `=` привязывает имя к числу.

```python
>>> def greet(name, greeting="Привет"):
...     return greeting + ", " + name
...
>>> type(greet)
<class 'function'>
>>> greet("Тамура")
'Привет, Тамура'
>>> greet("Тамура", "Доброй ночи")
'Доброй ночи, Тамура'
>>> greet(greeting="Эй", name="Тамура")
'Эй, Тамура'
```

Аргумент можно передать по позиции или по имени. По имени — понятнее, когда
аргументов больше двух: `collect_alerts(readings, 96, 104, found=old)` читается
без справки.

### Когда вычисляется значение по умолчанию

Ровно один раз — когда выполняется `def`. Значение сохраняется в самой функции:

```python
>>> collect_alerts.__defaults__
([],)
```

Это тот самый список, общий для всех вызовов. Каждый вызов без `found` получает
не новый пустой список, а **этот**. В s01e03 было видно, что одно значение под
восемью именами — источник сюрпризов. Здесь то же самое, только второе имя
появляется при каждом вызове.

Пока умолчание неизменяемо — строка, число, кортеж, — это не важно: `prefix=
"ТРЕВОГА"` безопасен, потому что строку нельзя испортить. Беда начинается, когда
умолчание — список или словарь, а функция его меняет.

### `None` как маркер

Обычное лечение — умолчание `None` и новый объект внутри:

```python
def collect_alerts(readings, low, high, found=None):
    if found is None:
        found = []
    ...
```

Теперь `[]` выполняется при каждом вызове, и каждый вызов без `found` получает
свой список. Тот, кто передал `found`, получает договорённость: функция допишет в
его список и вернёт его же.

Проверять надо именно `is None`. Соблазнительное `found = found or []` ломается
на пустом списке: пустой список ложен (s01e01), и переданный пустой `found`
молча подменяется новым. Вызывающий ждёт свои тревоги в своём списке и находит
его пустым.

### Имя внутри и снаружи

Имена, которым присваивают внутри функции, — **локальные**: они живут, пока
выполняется вызов, и не видны снаружи.

```python
>>> x = 10
>>> def change():
...     x = 20
...     return x
...
>>> change(), x
(20, 10)
```

Читать внешнее имя функция может, но надеяться на это — путь к той же ошибке:
общий накопитель снаружи функции ведёт себя как список-умолчание. Всё, что функции
нужно, она получает аргументами и отдаёт через `return`. Строку для `format_alert`
удобно собрать f-строкой — приём из [`theory.md`](theory.md), раздел 9.

## Проверка: SELENE задаёт вопросы

```
[КАНАЛ 0 · УЗЕЛ НЕ УКАЗАН]
ТАМУРА ВСЁ ЕЩЁ ДЕРЖИТ БЛАНК НАРЯДА. ТРИ ВОПРОСА, ПОКА ОН ЕГО НЕ ОТПРАВИЛ.
```

**1.** «Почему перезапуск программы "чинил" функцию Рейеса?»

<details><summary>Ответ</summary>

Список-умолчание создаётся при выполнении `def`, то есть при каждом запуске
программы заново. Внутри одного запуска он общий для всех вызовов, поэтому ошибка
появляется только со второго вызова. Первая проверка за ночь всегда верна.
</details>

**2.** «`prefix="ТРЕВОГА"` — тоже умолчание, вычисленное один раз. Почему с ним
ничего не случается?»

<details><summary>Ответ</summary>

Строка неизменяема. Её можно только заменить новой, а сам объект в `__defaults__`
никто испортить не может. Опасно изменяемое умолчание, которое функция меняет.
</details>

**3.** «Чем плохо `found = found or []`?»

<details><summary>Ответ</summary>

`or` проверяет истинность, а не «передано ли». Пустой список ложен, поэтому
переданный пустой `found` заменяется новым, и вызывающий не получает тревоги в
свой список. «Не передано» — это `found is None`.
</details>

## Разбор типичных ошибок

1. **`found=[]` или `counts={}` в подписи.** Одно значение на все вызовы. Ошибка
   Рейеса; проявляется со второго вызова.
2. **Общий накопитель снаружи функции.** Та же ошибка другими словами: результат
   зависит от истории вызовов.
3. **`found = found or []`.** Переданный пустой список подменяется новым.
4. **`found = list(found)`.** Копия вместо дописывания: прежнее содержимое на
   месте, но вызывающий его не получает, потому что вернулся другой список.
5. **`<=` вместо `<`.** Ровно 96 и ровно 104 кПа — допустимые значения.
6. **Узлы без тревог с нулём в счётчике.** Договорённость: в словаре только узлы,
   у которых тревоги есть.
