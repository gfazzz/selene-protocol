# Теория — s01e04

## 1. Как словарь находит ключ, не перебирая

Словарь — это **хеш-таблица**. Из ключа функция `hash` вычисляет целое число, по
нему выбирается ячейка в массиве, и в ней лежит пара «ключ → значение». Чтобы
найти ключ, не надо смотреть остальные: достаточно снова вычислить хеш.

Два разных ключа могут дать одну ячейку: это называется коллизией. Тогда Python
пробует следующую ячейку по своему правилу и сравнивает ключи через `==`. Поэтому
у ключа должны быть согласованы две вещи: равные значения дают равный хеш.

В среднем поиск не зависит от числа ключей. Поиск `in` в списке, наоборот,
проверяет элементы по очереди, пока не найдёт. Для трёх тысяч узлов это разница
между одним шагом и тремя тысячами на каждый вопрос, а сводка Рейеса задавала
такой вопрос на каждом пакете.

> *SELENE, в отладочном канале: «Сводка Рейеса читала поток три тысячи раз за
> ночь. Я читаю его один. Возможно, поэтому меня нет в справочнике: у меня нет
> времени ждать утверждения».*

## 2. Почему ключ должен быть неизменяемым

Представь, что ключом стал список `["0214"]`, а потом в него дописали элемент.
Хеш изменился бы, но пара лежит в ячейке, выбранной по старому хешу. Поиск по
новому значению пойдёт в другую ячейку и ничего не найдёт; старый ключ найти тоже
нельзя, потому что его больше нет. Python не допускает такой ситуации:

```python
>>> hash(["0214"])
TypeError: unhashable type: 'list'
>>> hash(("0214", "O2")) == hash(("0214", "O2"))
True
>>> hash(("0214", ["O2"]))
TypeError: unhashable type: 'list'
```

Кортеж хешируется, только если хешируется всё, что внутри. Вот первая причина
неизменяемости строк из s01e01: строка годится в ключ.

## 3. Равные ключи — один ключ

Ключи сравниваются через `==`, а в s01e01 выяснилось, что `True` — это целое:

```python
>>> {1: "a", True: "b", 1.0: "c"}
{1: 'c'}
```

Три записи, один ключ: `1 == True == 1.0`, и хеши у них равны. Остаётся первый
ключ и последнее значение. На практике это повод не смешивать в ключах числа,
флаги и строки, а выбрать один тип. Для узлов это строка, и `int(node)` в ключе
сломал бы сравнение со справочником.

## 4. Порядок в словаре

С Python 3.7 словарь гарантированно помнит порядок добавления ключей. В 3.6 это
было свойством реализации, а не обещанием языка. Порядок удобен для вывода, но
сводка не должна от него зависеть: при сравнении словарей `==` его не учитывает.

```python
>>> {"0214": 3, "0000": 7} == {"0000": 7, "0214": 3}
True
```

Тест серии проверяет именно это: перемешанный поток должен дать равный словарь.
Порядок ключей при этом будет другим, и это нормально.

## 5. Множество: словарь без значений

Множество устроено как словарь, у которого есть только ключи. Отсюда его
свойства: нет повторов, нет порядка, элемент должен хешироваться, проверка `in`
быстрая.

Порядка нет по-настоящему. Хеш строки в Python случайно «солится» при каждом
запуске интерпретатора, чтобы злоумышленник не мог подобрать ключи с
одинаковым хешем и замедлить программу. Поэтому одно и то же множество строк
может печататься в разном порядке при разных запусках. Тест, сравнивающий
напечатанное множество со строкой, нестабилен; тест, сравнивающий множества,
стабилен. Зафиксировать соль можно переменной окружения `PYTHONHASHSEED`, но
правильнее не зависеть от порядка вовсе.

## 6. Алгебра множеств как проверка

Операции над множествами — не только способ вычислить ответ, но и способ его
проверить. Если `silent = registry - heard`, то всегда:

- `silent & heard` пусто — узел не может одновременно молчать и докладывать;
- `silent | (heard & registry)` равно `registry` — вместе они дают весь справочник.

Эти тождества выполняются при любом потоке, и тест проверяет их на
сгенерированных данных вместо того, чтобы хранить готовый ответ. Это и есть ось
«свойство и инвариант» из ТЗ курса: свойство нельзя подогнать под конкретный
пример.

| Операция | Значок | Метод | Что даёт |
|---|---|---|---|
| разность | `a - b` | `a.difference(b)` | есть в `a`, нет в `b` |
| объединение | `a \| b` | `a.union(b)` | есть хотя бы в одном |
| пересечение | `a & b` | `a.intersection(b)` | есть в обоих |
| симметрическая разность | `a ^ b` | `a.symmetric_difference(b)` | ровно в одном |

У каждой операции есть вариант на месте: `-=`, `|=`, `&=`, `^=` и методы с
окончанием `_update`. Они меняют левое множество, и вызывающий, передавший его,
увидит изменение. Внутри функции, которая получила множество аргументом, эти
варианты почти всегда ошибка.

## 7. `frozenset`

Неизменяемое множество. Его можно сделать ключом словаря или элементом другого
множества. Справочник смены разумно хранить как `frozenset`: тогда случайное
`registry.add(node)` сразу даст `AttributeError`, а не тихую порчу.

```python
>>> frozen = frozenset({"0001", "0002"})
>>> frozen - {"0002"}
frozenset({'0001'})
```

Разность работает и возвращает новое множество. `frozen -= {"0002"}` ошибки не
даёт, но и исходный объект не меняет: имя молча перевешивается на новый, как в
s01e01, и вызывающий этой «правки» не увидит.

## 8. `get`, `setdefault` и что будет дальше

Подсчёт можно записать тремя способами. `counts.get(node, 0) + 1` — явный и
понятный. `counts.setdefault(node, 0)` возвращает значение и заодно записывает
ноль, если ключа не было; для счётчиков он многословнее. В стандартной
библиотеке есть готовый счётчик `collections.Counter`, но импорт модулей — тема
s01e06, а сегодня важнее понять, что такой счётчик делает внутри: ровно то, что
делает твой код.

## 9. Компромисс: справочник или поток

Сводка Рейеса шла от справочника к потоку и поэтому видела только известное.
Твоя идёт от потока, и неизвестное становится видно само. У каждого направления
своя цена: от справочника видно молчащих, от потока — лишних. Нужны оба вопроса,
и множества позволяют задать их одной операцией каждый.
