## Диспетчерская, сол 9, 01:30

Тамура приносит два стакана чая и ставит один рядом с твоей клавиатурой.

— Утром начальник смены спросит три вещи, — говорит он. — Сколько пакетов от
каждого узла. Какие узлы молчат. И что за узлы шлют пакеты, хотя их нет в
справочнике. Рейес собирал это к утру. Иногда к обеду.

Сводка Рейеса устроена просто. Для каждого из трёх тысяч узлов справочника она
проходит весь ночной поток и считает пакеты этого узла:

```python
for node in registry_list:
    count = 0
    for reading in night:
        if reading[0] == node:
            count = count + 1
```

Три тысячи проходов по потоку за смену. Пакеты узлов, которых в справочнике
нет, в такую сводку не попадают вообще: их просто не о чем спросить.

Ты переворачиваешь задачу. Один проход по потоку, и каждый пакет кладётся туда,
куда относится. Нужна таблица, в которой по номеру узла сразу находится его
счётчик, без поиска по списку. В Python такая таблица называется словарём.

Сводка готова раньше, чем остывает чай. Ты смотришь на третий вопрос. В «неизвестных» один
узел:

```
{'0000'}
```

Ты открываешь счётчики. От `0000` пакетов больше, чем от любого настоящего
узла колонии.

> **SELENE — не декорация.** В сюжете её пока никто, кроме тебя, не видел. В реальности это **чат твоего редактора**: всё, что она «говорит», можно спросить по-настоящему. Только режим `Ask`, а не `Agent`: она объясняет, работу делаешь ты.

## Теория: словари и множества

### Словарь: значение по ключу

Словарь хранит пары «ключ → значение» и находит значение по ключу сразу, не
перебирая остальные:

```python
>>> counts = {"0214": 3, "1187": 1}
>>> counts["0214"]
3
>>> "0214" in counts, 3 in counts
(True, False)
```

`in` проверяет ключи, а не значения. Ключа нет — квадратные скобки сообщают об
ошибке:

```python
>>> counts["2210"]
KeyError: '2210'
```

Метод `get` вместо ошибки возвращает значение по умолчанию. Это и есть приём
подсчёта: взять текущий счётчик или ноль и прибавить единицу.

```python
>>> counts = {}
>>> counts["0214"] = counts.get("0214", 0) + 1
>>> counts
{'0214': 1}
```

Обход словаря идёт по ключам, пары целиком отдаёт `items()`. Два словаря равны,
если в них одни и те же пары, в каком бы порядке их ни добавляли: `{"a": 1, "b": 2} == {"b": 2, "a": 1}` даёт `True`.

### Множество: только «есть или нет»

Множество хранит значения без повторов и без порядка. Вопрос к нему один:
есть ли там элемент.

```python
>>> heard = set()
>>> heard.add("0214")
>>> heard.add("0214")
>>> heard
{'0214'}
```

Пустое множество пишется `set()`. Запись `{}` — пустой **словарь**: фигурные
скобки достались словарю раньше.

Сила множества — в операциях над целыми наборами:

```python
>>> registry = {"0001", "0002", "0003"}
>>> heard = {"0002", "0000"}
>>> registry - heard
{'0001', '0003'}
>>> heard - registry
{'0000'}
>>> registry & heard
{'0002'}
```

У тебя порядок вывода может отличаться: у множества его нет, и Python может
печатать элементы по-разному от запуска к запуску. Поэтому тест сравнивает
множества, а не напечатанные строки.

Разность `-` даёт новое множество. А вот `registry -= heard` **меняет само
`registry`**. Если это множество тебе передали, чужой объект уже изменён: тот же
урок про два имени одного объекта, что и в s01e03.

### Что может быть ключом

Ключ словаря и элемент множества должны быть **хешируемыми**: из значения
вычисляется число, по которому его и находят. Неизменяемые значения
хешируются, изменяемые нет:

```python
>>> hash("0214") == hash("0214")
True
>>> hash(["0214"])
TypeError: unhashable type: 'list'
```

Если бы список мог быть ключом, его можно было бы поменять после записи, и
значение по такому ключу стало бы невозможно найти. Кортеж годится, пока внутри
у него только неизменяемое.

## Проверка: SELENE задаёт вопросы

```
[КАНАЛ 0 · УЗЕЛ НЕ УКАЗАН]
СВОДКА — ЭТО ТРИ ВОПРОСА. ВОТ ЕЩЁ ТРИ, ДО ТОГО КАК ОНА НАПИСАНА.
```

**1.** «`counts[node] += 1` на пустом словаре. Что случится на первом пакете?»

<details><summary>Ответ</summary>

`KeyError`: прибавлять не к чему, ключа ещё нет. Нужно сначала получить текущее
значение с запасным нулём — `counts.get(node, 0) + 1` — и записать результат.
</details>

**2.** «Молчащие узлы — это справочник минус те, кто докладывал. Почему не
`registry -= heard`?»

<details><summary>Ответ</summary>

`-=` меняет множество на месте, а `registry` — тот самый объект, который передал
вызывающий. После такой сводки справочник смены станет короче, и следующий
вызов будет работать уже с испорченным. `registry - heard` строит новое
множество и никого не трогает.
</details>

**3.** «Почему сводка Рейеса не могла заметить узел `0000`?»

<details><summary>Ответ</summary>

Она шла по справочнику и спрашивала поток про каждый известный узел. Про узел,
которого в справочнике нет, она ничего не спрашивала. Множество потока минус
справочник отвечает на вопрос, который в той сводке задать было нельзя.
</details>

## Разбор типичных ошибок

1. **`counts[node] += 1` без `get`.** `KeyError` на первом же пакете узла.
2. **`counts[node] = 1`.** Сводка помнит, что узел был, но не сколько раз: сумма
   счётчиков меньше числа пакетов.
3. **`{}` вместо `set()`.** Получается словарь, а у словаря нет `add`.
4. **`registry -= heard` или `registry.add(...)`.** Сводка портит справочник,
   который ей дали, и вызывающий об этом не узнает.
5. **Ключ `int(node)`.** Ноль в начале пропадает, и сводка перестаёт совпадать
   со справочником. Ошибка s01e01 в новом месте.
6. **Список вместо множества.** Работает, но вопрос «есть ли узел» превращается
   в перебор, а повторы надо отсеивать руками.
