# Теория — s01e01

## 1. Всё есть объект

В Python у каждого значения есть три свойства: **тождество**, **тип** и
**значение**. Посмотреть первые два можно прямо сейчас:

```python
>>> reading = 20.9
>>> id(reading)     # у тебя будет другое число
4378912304
>>> type(reading)
<class 'float'>
```

`id` различает объекты, живущие одновременно. `type` говорит, какие операции
объекту доступны. Тип принадлежит значению, а не имени, и в этом главное отличие от
C из соседнего курса: там переменная объявляется с типом и занимает ячейку памяти
этого размера.

> *SELENE, в отладочном канале: «Рейес, видимо, думал, что `int` — это про внешний
> вид. Его можно понять. Регламент колонии устроен так же».*

## 2. Имена, а не коробки

Обычная метафора «переменная — коробка» в Python подводит. Точнее думать о ярлыке:

```python
>>> a = "O2"
>>> b = a
>>> a = "N2"
>>> b
'O2'
```

`b = a` привязывает ещё один ярлык к тому же объекту. `a = "N2"` перевешивает ярлык
`a` на другой объект, а `b` остаётся на месте. Копирования не было ни разу.

Отсюда и «динамическая типизация»: имя может указывать на что угодно, и проверка
типа происходит при выполнении операции.

```python
>>> x = 118
>>> x = "118"    # допустимо: тот же ярлык, другой объект
```

Допустимо, но обычно вредно. Если `x` то число, то строка, читателю приходится
помнить, что сейчас на нём висит. Строгая типизация при этом никуда не делась:
`"118" + 1` остаётся ошибкой. Динамическая и слабая — разные свойства.

С изменяемыми объектами ярлыки ведут себя интереснее: два имени могут менять один
список. Это предмет s01e05.

## 3. Почему строки неизменяемы

Неизменяемость даёт три вещи.

**Строку можно использовать как ключ.** Справочник узлов находит запись по `"0214"`.
Если бы ключ мог измениться после записи, найти запись стало бы невозможно.

**Строки можно разделять.** Раз никто не может её изменить, одну и ту же строку
безопасно держать под многими именами, не копируя.

**Рассуждать проще.** Ты отдаёшь строку в функцию и точно знаешь, что она вернётся
такой же. Ни `strip`, ни `replace`, ни `upper` не меняют исходную строку.

Цена: склейка в цикле создаёт новую строку на каждом шаге. Как делать это быстрее,
разберём позже.

## 4. Целые без предела, вещественные с пределом

В `int` нет верхней границы, кроме памяти:

```python
>>> 2 ** 100
1267650600228229401496703205376
```

У `float` границы есть: это 64-битное число стандарта IEEE 754 с 53 битами на
мантиссу. Отсюда две вещи, которые стоит увидеть своими глазами:

```python
>>> 0.1 + 0.2
0.30000000000000004
>>> int(float("9007199254740993"))
9007199254740992
```

Первая строка: `0.1` не имеет точного двоичного представления, как `1/3` не имеет
точного десятичного. Вторая: `2**53 + 1` уже не помещается в мантиссу, и ближайшее
представимое значение оказывается на единицу меньше. Ошибки при этом нет.

Показание датчика может позволить себе такую неточность: сам датчик менее точен.
Номер пакета и деньги — нет. К точности `float` вернёмся в S4, к деньгам — в S5.

## 5. `bool` — это целое

```python
>>> isinstance(True, int)
True
>>> True + True
2
```

Исторически `bool` появился в Python позже и был сделан подклассом `int`, чтобы не
сломать старый код. Поэтому `type(result) is bool` и `isinstance(result, int)` —
разные вопросы, и тест серии спрашивает первое: `0` и `False` равны, но ответ
«0» на вопрос «есть ли тревога?» — не тот тип.

Истинность определена для всех объектов. По умолчанию всё истинно, кроме нулей,
пустых коллекций, `None` и `False`. Правило удобно для `if items:` и плохо подходит
для разбора данных: `bool("0")`, `bool("False")`, `bool("нет")` одинаково `True`.

У Рейеса был шанс это заметить: лампа горела всегда. Постоянно истинная проверка
ничего не проверяет. То же самое правило действует для тестов этого курса.

## 6. Как выбирать тип

Вопрос один: **какие операции имеют смысл?**

| Что это | Тип | Почему |
|---|---|---|
| номер узла `0214` | `str` | не складывают, ноль значим |
| номер пакета `118` | `int` | сравнивают, вычитают, считают пропуски |
| показание `20.9` | `float` | дробное, измерено с погрешностью |
| флаг тревоги | `bool` | только да или нет |

Похожее решение придётся принимать постоянно: почтовый индекс, номер телефона, номер
счёта, версия `1.10`. Последний пример поучителен: как `float` это `1.1`, и версия
десять превращается в версию один.

## 7. Что принимают `int` и `float`

Они принимают больше, чем кажется. Каждую строку легко проверить самому:

```python
>>> int("1_000")
1000
>>> int("٣")          # арабско-индийская цифра
3
>>> float("nan")
nan
>>> float("infinity")
inf
>>> float("1e3")
1000.0
```

`float("nan")` — повод насторожиться: пакет с показанием `nan` пройдёт сегодняшний
разбор. Тест серии этого не проверяет. Показание и его допустимость — разные задачи:
проверка диапазона появится в s01e03, а своя ошибка на неверное поле — в s01e10.

Запятая, напротив, не принимается: `float("20,90")` — `ValueError`. Выгрузки с
десятичной запятой ещё встретятся в S3.

## 8. Литералы и ноль в начале

Python 3 не позволяет написать ноль в начале целого литерала:

```python
>>> x = 0214
SyntaxError: leading zeros in decimal integer literals are not permitted; use an 0o prefix for octal integers
```

В Python 2 такая запись означала восьмеричное число. Тот же смысл сохраняется в C:
`0214` там равно `140`. Python 3 предпочёл запретить неоднозначность, чем молча
выбрать одно прочтение. Это хороший образец: **отказ лучше догадки**. Тот же принцип
серия требует от `read_sequence("12.5")`.

## 9. Компромисс: ошибка или значение по умолчанию

Что делать с мусорным полем? Варианта три: упасть, вернуть особое значение, вернуть
что-то правдоподобное. Третий хуже всех: `0.0` в поле кислорода неотличим от
настоящего нуля. Второй требует, чтобы каждый вызывающий помнил о проверке. Сегодня
выбираем первый: ошибка видна, и её нельзя случайно не заметить. Отбраковка без
остановки всего потока появится в s01e10, журнал отбраковки — в s03e04.
