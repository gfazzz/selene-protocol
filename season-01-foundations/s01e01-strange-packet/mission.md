## Обстановка

Сводка считает живой узел мёртвым, а каждый пакет тревогой. Причина — две строчки,
которые судят о значении по его виду. Сводку придётся строить заново, и начинается
она с разбора одного пакета.

## Приказ

Написать `artifacts/toolkit/reading.py`: пять функций, каждая превращает одно поле
пакета в значение нужного типа.

## Данные

Пакет — строка из пяти полей через точку с запятой:

```
0214;O2;20.90;118;0
```

| Поле | Функция | Что возвращает | Пример |
|---|---|---|---|
| узел | `read_node` | `str` | `"0214"` → `"0214"` |
| датчик | `read_sensor` | `str` | `"  O2 "` → `"O2"` |
| значение | `read_value` | `float` | `"20.90"` → `20.9` |
| номер пакета | `read_sequence` | `int` | `"118"` → `118` |
| тревога | `read_alarm` | `bool` | `"0"` → `False` |

Функция `parse_reading` уже написана в каркасе: она разрезает строку и зовёт твои
пять. Флаг принимает только `"0"` и `"1"`: другие значения разберём в s01e07.

## Критерии приёмки

- [ ] Узел остаётся строкой и не теряет нули в начале.
- [ ] Узел и датчик не содержат пробелов по краям.
- [ ] Пробелы внутри кода датчика сохраняются.
- [ ] Показание всегда `float`, даже если в поле нет точки.
- [ ] Мусор в показании даёт `ValueError`, а не придуманное число.
- [ ] Номер пакета — `int`, большой номер не искажается.
- [ ] Дробный номер даёт `ValueError`, а не округляется.
- [ ] `"0"` даёт `False`, `"1"` — `True`, пробелы по краям не влияют.
- [ ] Странный пакет разбирается по тем же правилам, что и обычный.
- [ ] `make test` → 27 зелёных проверок.
