## Чему ты научишься

- Различать **модуль** (файл) и **пакет** (каталог с `__init__.py`).
- Понимать, что происходит при `import`: код модуля **выполняется**, один раз.
- Объявлять, что пакет отдаёт наружу: явный импорт и `__all__`.
- Приёму, который дороже синтаксиса: **импорт не должен иметь последствий.** Всё,
  что делает работу, ждёт, пока его позовут.

## Теория: модули и пакеты, импорт

### Модуль — это файл, который выполняют

Любой файл `.py` — модуль. `import scan` находит файл `scan.py` и **выполняет его
целиком**, сверху вниз. Определения функций при этом только создают функции, а вот
`print` в начале файла действительно печатает. Так и работает баннер Рейеса.

Выполняется модуль один раз за запуск программы. Готовый модуль лежит в словаре
`sys.modules`, и второй `import` просто берёт его оттуда:

```python
import toolkit   # баннер
import toolkit   # тишина: модуль уже загружен
```

Поэтому побочный эффект импорта особенно коварен: он случается один раз, в
непредсказуемом месте, у того, кто первым импортировал.

### Пакет — это каталог

Каталог с файлом `__init__.py` — пакет. `import toolkit` выполняет
`toolkit/__init__.py`. Модули внутри доступны через точку:

```python
import toolkit.scan
toolkit.scan.first_gap([5, 6, 8])   # 7
```

Внутри пакета модули ссылаются друг на друга **относительно**: точка значит «из этого
же пакета».

```python
from .scan import first_gap
```

Запустить такой файл напрямую нельзя:

```
$ python toolkit/scan.py
ImportError: attempted relative import with no known parent package
```

Файл, запущенный напрямую, не знает, что он часть пакета.

### `import` и `from … import`

```python
import toolkit.reading          # имя toolkit, путь toolkit.reading.read_node
from toolkit import read_node   # имя read_node, сразу функция
```

Оба варианта загружают модуль одинаково, разница в том, какое имя появится у
тебя. `from … import` привязывает имя к тому же объекту, что лежит в модуле: это не
копия. Проверить можно знакомым из s01e03 `is`.

### Что пакет обещает: `__all__`

`from toolkit import *` берёт всё, что не начинается с подчёркивания, — включая
загруженные подмодули и любые служебные переменные. Если в пакете есть список
`__all__`, звёздочка берёт ровно его:

```python
__all__ = ["read_node", "first_gap"]
```

`__all__` — это договор: «вот что я обещаю и не буду менять без предупреждения».
Остальное — внутренности. Звёздочка в своём коде всё равно рискованна: непонятно,
откуда пришло имя. Но если кто-то её напишет, получит он только обещанное.

### `__name__` и `__main__`

У каждого модуля есть `__name__`. При импорте это имя модуля, `"toolkit.scan"`. При
запуске файла как программы — `"__main__"`. Отсюда знакомая строчка:

```python
if __name__ == "__main__":
    main()
```

Она отделяет «что я умею» от «что сделать, если меня запустили». Для пакета то же
делает файл `__main__.py`: `python -m toolkit` выполняет сначала `__init__.py`,
потом `__main__.py`. Сводка в этой серии устроена именно так и уже написана.
Чтение файла и `with` в ней — приём записи: файлы разберём в s01e08, `with` — в
s02e05.

## Проверка: SELENE задаёт вопросы

```
[КАНАЛ 0 · УЗЕЛ НЕ УКАЗАН]
ТРИ ВОПРОСА. ОКАФОР ВЕРНЁТСЯ ЧЕРЕЗ ДВАДЦАТЬ МИНУТ. КОФЕ ЗДЕСЬ ПЛОХОЙ, НО НЕ НАСТОЛЬКО.
```

**1.** «Окафор импортирует `toolkit` в трёх своих модулях. Сколько раз выйдет баннер?»

<details><summary>Ответ</summary>

Один раз за запуск. Первый `import` выполнит `__init__.py` и положит модуль в
`sys.modules`, остальные возьмут его оттуда. Поэтому баннер и прожил так долго:
лишнюю строку в начале отчёта никто не связывал с импортом.
</details>

**2.** «Откуда берётся `toolkit.lock` в каталоге Окафор, а не в каталоге пакета?»

<details><summary>Ответ</summary>

`open("toolkit.lock", "w")` с относительным путём пишет в **текущий** каталог
процесса — того, кто импортирует, а не того, кто написал пакет. Импорт выполняется
от имени чужой программы, в её каталоге, с её правами. Как устроена работа с
файлами, разберём в s01e08.
</details>

**3.** «Почему в `from toolkit import *` попал объект `lock`?»

<details><summary>Ответ</summary>

Без `__all__` звёздочка берёт все имена пакета без подчёркивания в начале. `lock` —
переменная, оставшаяся в `__init__.py` после записи файла. Туда же попали и
подмодули: `reading`, `scan` и остальные.
</details>

## Разбор типичных ошибок

1. **Убрать `print`, оставить файл.** Вывод чистый, но `toolkit.lock` продолжает
   появляться в чужих каталогах.
2. **Оставить звёздочки без `__all__`.** Работает, но наружу уходят модули и всё
   случайное. Звёздочки с `__all__` допустимы: обещанное всё равно ограничено.
3. **Записать в `__all__` модули.** `"reading"` — не функция, и обещать её не нужно.
4. **Переписать функцию в `__init__.py` «для удобства».** Получится копия: исправление
   в модуле до пакета не дойдёт.
5. **`__version__ = 0.1`.** Версия — строка. Как число `0.10` равно `0.1`.

— Опять сбой справочника. Узла `0000` нет, а он в каждой сводке.

Ты ничего не отвечаешь. Она смотрит на тебя дольше, чем нужно, и уходит на свою
