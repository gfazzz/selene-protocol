# Теория — s01e06

## 1. Как словарь находит ключ, не перебирая

Словарь — это **хеш-таблица**. Из ключа функция `hash` вычисляет целое число, по
нему выбирается ячейка в массиве, и в ней лежит пара «ключ → значение». Чтобы
найти ключ, не надо смотреть остальные: достаточно снова вычислить хеш.

Два разных ключа могут дать одну ячейку: это называется коллизией. Тогда Python
пробует следующую ячейку по своему правилу и сравнивает ключи через `==`. Поэтому
у ключа должны быть согласованы две вещи: равные значения дают равный хеш.

В среднем поиск не зависит от числа ключей. Поиск по списку, наоборот,
проверяет элементы по очереди, пока не найдёт. Для трёх тысяч узлов это разница
между одним шагом и тремя тысячами на каждый вопрос, а сводка Рейеса задавала
такой вопрос для каждого узла справочника.

> *SELENE, в отладочном канале: «Сводка Рейеса читала поток три тысячи раз за
> ночь. Я читаю его один. Возможно, поэтому меня нет в справочнике: у меня нет
> времени ждать утверждения».*

## 2. Почему ключ должен быть неизменяемым

Представь, что ключом стал список `["0214"]`, а потом в него дописали элемент.
Хеш изменился бы, но пара лежит в ячейке, выбранной по старому хешу. Поиск по
новому значению пойдёт в другую ячейку и ничего не найдёт; старый ключ найти тоже
нельзя, потому что его больше нет. Python не допускает такой ситуации:

```python
>>> hash(["0214"])
TypeError: unhashable type: 'list'
>>> hash(("0214", "O2")) == hash(("0214", "O2"))
True
>>> hash(("0214", ["O2"]))
TypeError: unhashable type: 'list'
```

Кортеж хешируется, только если хешируется всё, что внутри. Вот первая причина
неизменяемости строк из s01e01: строка годится в ключ.

Сообщение об ошибке для словаря с ключом-списком в разных версиях звучит
по-разному: в 3.14 это «cannot use 'list' as a dict key (unhashable type:
'list')». Суть одна, поэтому примеры здесь идут через `hash`.

## 3. Равные ключи — один ключ

Ключи сравниваются через `==`, а в s01e01 выяснилось, что `True` — это целое:

```python
>>> {1: "a", True: "b", 1.0: "c"}
{1: 'c'}
```

Три записи, один ключ: `1 == True == 1.0`, и хеши у них равны. Остаётся первый
ключ и последнее значение. На практике это повод не смешивать в ключах числа,
флаги и строки, а выбрать один тип. Для узлов это строка, и `int(node)` в ключе
сломал бы сравнение со справочником.

## 4. Порядок в словаре

С Python 3.7 словарь гарантированно помнит порядок добавления ключей. В 3.6 это
было свойством реализации, а не обещанием языка. Порядок удобен для вывода, но
сводка не должна от него зависеть: при сравнении словарей `==` его не учитывает.

```python
>>> {"0214": 3, "0000": 7} == {"0000": 7, "0214": 3}
True
```

Тест серии проверяет именно это: перемешанный поток должен дать равный словарь.
Порядок ключей при этом будет другим, и это нормально.

Менять набор ключей во время обхода нельзя:

```python
>>> d = {"a": 1}
>>> for key in d:
...     d["b"] = 2
RuntimeError: dictionary changed size during iteration
```

Если нужно что-то удалить или добавить по итогам обхода, сначала собери, что
менять, а потом меняй.

## 5. Три способа завести значение

| Запись | Что делает | Когда |
|---|---|---|
| `d.get(key, 0) + 1` | читает с запасным значением, ничего не пишет | счётчики |
| `d.setdefault(key, [])` | если ключа нет, записывает значение; возвращает то, что лежит | группировка |
| `d[key] += 1` | читает и пишет; без ключа — `KeyError` | когда ключ точно есть |

`setdefault` удобен для списков, потому что возвращает **тот самый** объект, что
лежит в словаре, и `.append` дописывает прямо в него:

```python
>>> c = {}
>>> c.setdefault("n", 0)
0
>>> c
{'n': 0}
```

В стандартной библиотеке есть готовые `collections.Counter` и
`collections.defaultdict`, но импорт модулей — тема s01e09, а сегодня важнее
понять, что они делают внутри: ровно то, что делает твой код.

## 6. Один объект на всех

`dict.fromkeys(keys, value)` кладёт под каждый ключ **одно и то же** значение.
Для числа это безопасно: числа неизменяемы. Для списка — нет:

```python
>>> grouped = dict.fromkeys(["0389", "0214"], [])
>>> grouped["0389"] is grouped["0214"]
True
```

Это ошибка s01e05 с табло, только спрятанная внутри словаря. То же даёт
`empty = []` перед циклом и `setdefault(node, empty)`: под всеми ключами окажется
один `empty`. Правильно создавать новый список на каждый новый ключ.

## 7. «Последний» — по чему?

Поток приходит не по порядку: ретранслятор задерживает пакеты и досылает их
позже. Отсюда два разных «последних»: пришедший последним и с наибольшим
номером. Состояние узла описывает второй.

Чтобы выбрать по номеру, рядом со значением надо помнить номер. Два словаря с
одинаковыми ключами — узел → номер и узел → значение — самый прямой способ: на
каждом пакете сравниваешь его номер с запомненным и обновляешь оба словаря, если
новый больше. Тест проверяет свойство: перемешанный поток даёт то же самое.

## 8. Компромисс: проход на вопрос или один проход

Сводка Рейеса шла от справочника к потоку: для каждого узла — свой проход. Это
просто писать и легко проверить глазами, но цена растёт как «узлы × пакеты».
Словарь даёт один проход на все узлы сразу и стоит памяти под таблицу. Для трёх
тысяч узлов это хорошая сделка; когда таблица не влезает в память, выбор
становится интереснее, и к нему курс вернётся в S13.
