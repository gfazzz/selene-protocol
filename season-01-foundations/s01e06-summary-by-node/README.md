## Диспетчерская, сол 9, 01:30

Тамура приносит два стакана чая и ставит один рядом с твоей клавиатурой.

— Утром начальник смены спросит две вещи, — говорит он. — Сколько пакетов от
каждого узла за ночь. И что каждый узел показал последним. Рейес собирал это к
утру. Иногда к обеду.

Сводка Рейеса устроена просто. Для каждого из трёх тысяч узлов справочника она
проходит весь ночной поток и считает пакеты этого узла:

```python
for node in registry_list:
    count = 0
    for reading in night:
        if reading[0] == node:
            count = count + 1
```

Три тысячи проходов по одному и тому же потоку. А последнее показание Рейес брал
просто: что пришло позже, то и последнее. Тамура хмурится на табло:

— 0389 показывает 100,2. Там же спад был, на него наряд.

Ты открываешь сырой поток. Последний по номеру пакет узла 0389 — 97,1. Но
ретранслятор задержал один пакет постарше, и тот пришёл в диспетчерскую
последним. Номер у него меньше. Табло поверило порядку прихода.

Ты переворачиваешь задачу. Один проход по потоку, и каждый пакет кладётся туда,
куда относится. Нужна таблица, в которой по номеру узла сразу находится его
счётчик, его последнее показание и список всех показаний за ночь, без поиска по
списку. В Python такая таблица называется словарём.

Сводка готова раньше, чем остывает чай. Первая строка по числу пакетов — узел
`0000`. Его нет в справочнике, и пакетов от него больше, чем от любого настоящего.

```
[КАНАЛ 0 · УЗЕЛ НЕ УКАЗАН]
ТРИ ТЫСЯЧИ ПРОХОДОВ ПО ОДНОМУ ПОТОКУ.
ВЫ ЧИТАЕТЕ ГАЗЕТУ ОТДЕЛЬНО ДЛЯ КАЖДОЙ БУКВЫ.
```

> **SELENE — не декорация.** В сюжете её пакеты все видят, но считают сбоем справочника. В реальности это **чат твоего редактора**: всё, что она «говорит», можно спросить по-настоящему. Только режим `Ask`, а не `Agent`: она объясняет, работу делаешь ты.

## Теория: словари

### Значение по ключу

Словарь хранит пары «ключ → значение» и находит значение по ключу сразу, не
перебирая остальные:

```python
>>> counts = {"0214": 3, "1187": 1}
>>> counts["0214"]
3
>>> "0214" in counts, 3 in counts
(True, False)
```

`in` проверяет ключи, а не значения. Ключа нет — квадратные скобки сообщают об
ошибке:

```python
>>> counts["2210"]
KeyError: '2210'
```

Метод `get` вместо ошибки возвращает значение по умолчанию. Это и есть приём
подсчёта: взять текущий счётчик или ноль и прибавить единицу.

```python
>>> counts = {}
>>> counts["0214"] = counts.get("0214", 0) + 1
>>> counts
{'0214': 1}
```

### Обход и распаковка пар

Обход словаря идёт по ключам, пары целиком отдаёт `items()`, и их удобно
раскладывать по двум именам, как в s01e04:

```python
>>> for node, count in {"0214": 3, "0000": 7}.items():
...     print(node, count)
0214 3
0000 7
```

Словарь помнит порядок добавления, но равенство его не учитывает:
`{"a": 1, "b": 2} == {"b": 2, "a": 1}` — `True`. Тест сравнивает словари, а не печать.

### Список на каждый ключ

Чтобы собрать все показания узла, у каждого узла должен быть **свой** список.
`setdefault` возвращает значение по ключу, а если ключа нет — сначала записывает
переданное значение:

```python
>>> grouped = {}
>>> grouped.setdefault("0389", []).append(100.2)
>>> grouped.setdefault("0389", []).append(97.1)
>>> grouped
{'0389': [100.2, 97.1]}
```

Новый `[]` создаётся при каждом вызове, но записывается только при первом.
Ловушка рядом: `dict.fromkeys(nodes, [])` кладёт под все ключи **один и тот же**
список — это урок s01e05 в новом месте:

```python
>>> grouped = dict.fromkeys(["0389", "0214"], [])
>>> grouped["0389"].append(97.1)
>>> grouped
{'0389': [97.1], '0214': [97.1]}
```

### Что может быть ключом

Ключ должен быть **хешируемым**: из значения вычисляется число, по которому его
и находят. Неизменяемые значения хешируются, изменяемые нет:

```python
>>> hash("0214") == hash("0214")
True
>>> hash(["0214", "O2"])
TypeError: unhashable type: 'list'
>>> {("0214", "O2"): 1}
{('0214', 'O2'): 1}
```

Список можно поменять после записи, и значение по нему стало бы не найти.
Кортеж годится, пока внутри у него только неизменяемое.

## Проверка: SELENE задаёт вопросы

```
[КАНАЛ 0 · УЗЕЛ НЕ УКАЗАН]
СВОДКА — ЭТО ДВА ВОПРОСА. ВОТ ТРИ, ДО ТОГО КАК ОНА НАПИСАНА.
```

**1.** «`counts[node] += 1` на пустом словаре. Что случится на первом пакете?»

<details><summary>Ответ</summary>

`KeyError`: прибавлять не к чему, ключа ещё нет. `+=` сначала читает значение по
ключу. Нужно взять текущее значение с запасным нулём — `counts.get(node, 0) + 1`
— и записать результат.
</details>

**2.** «Табло Рейеса брало последнее пришедшее показание. Почему 0389 показал
100,2?»

<details><summary>Ответ</summary>

Задержанный пакет с меньшим номером пришёл позже свежего и перезаписал его.
«Последний» — это пакет с наибольшим номером, а не тот, что пришёл последним.
Для этого рядом со значением надо помнить и номер: второй словарь узел → номер.
</details>

**3.** «Почему все узлы получили одни и те же показания после
`dict.fromkeys(nodes, [])`?»

<details><summary>Ответ</summary>

`[]` вычислен один раз, и под каждым ключом лежит ссылка на этот единственный
список. `setdefault(node, [])` создаёт новый список на каждом вызове и
записывает его только для нового ключа.
</details>

## Разбор типичных ошибок

1. **`counts[node] += 1` без `get`.** `KeyError` на первом же пакете узла.
2. **`counts[node] = 1`.** Сводка помнит, что узел был, но не сколько раз: сумма
   счётчиков меньше числа пакетов.
3. **Последнее по приходу.** Задержанный пакет перезаписывает свежий. Ошибка
   табло Рейеса.
4. **`dict.fromkeys(nodes, [])` или общий `empty = []` в `setdefault`.** Один
   список на всех: показания одного узла видны у всех остальных.
5. **Ключ `int(node)`.** Ноль в начале пропадает, и сводка перестаёт совпадать
   со справочником. Ошибка s01e01 в новом месте.
6. **Ключ-список.** `TypeError: unhashable type: 'list'`. Нужна пара — бери
   кортеж.
