- Запускать модуль пакета как программу и отличать запуск от импорта.

- Разделять **stdout** и **stderr**: результат в одно место, жалобы в другое.
- Приёму, который дороже синтаксиса: **программа обязана честно сказать
  системе, получилось или нет.** Для этого есть код возврата.

## Теория: скрипт, аргументы, код возврата

### Программа говорит тремя способами

У каждой запущенной программы три выхода: **stdout** — результат для следующей
программы или файла, **stderr** — ошибки для человека у консоли, **код
возврата** — для системы. `print` по умолчанию пишет в stdout. В stderr — так:

`print("toolkit: нет файла", file=sys.stderr)` (после `import sys`).

Зачем два потока, видно в консоли: `команда > отчёт.txt` уводит в файл только
stdout, а ошибки остаются на экране. Скрипт Рейеса писал ошибку в stdout, и
она уехала в отчёт вместо цифр.

Код возврата после запуска лежит в `$?`: 0 — успех, 1 — общая ошибка, 2 —
программу неправильно вызвали. Расписание, CI и `make` смотрят только на код.

### Аргументы: `sys.argv` и `argparse`

Всё, что написано после имени программы, приходит в список `sys.argv`:

```
$ python3 -c "import sys; print(sys.argv)" a "b c"
['-c', 'a', 'b c']
```

Первый элемент — имя скрипта (для `-c` — строка `'-c'`), остальные — строки. Разбирать их руками —
забыть про `--help` и принять `abc` за границу. `argparse` разбирает по описанию:

```python
import argparse

parser = argparse.ArgumentParser(prog="toolkit")
commands = parser.add_subparsers(dest="command", required=True)
summary = commands.add_parser("summary", help="сводка по журналу")
summary.add_argument("log")
summary.add_argument("--low", type=float, default=96.0)
args = parser.parse_args(["summary", "shift.log", "--low", "97"])
args.command, args.log, args.low   # ('summary', 'shift.log', 97.0)
```

`type=float` превращает строку в число и сам ругается на `abc`, а справку
`--help` собирает из тех же описаний.

### Где `argparse` выходит из программы

На неверных аргументах `argparse` печатает подсказку в stderr и вызывает
`sys.exit(2)`. Это поднимает исключение `SystemExit`: функция не возвращается,
процесс завершается. Для программы это правильный код, но для `main`, которую
хочется вызвать из теста и получить ответ, — нет. Поэтому выход перехватывают
и превращают в обычный код возврата:

```python
try:
    args = parser.parse_args(argv)
except SystemExit as stop:
    return stop.code        # 2 на ошибке, 0 на --help
```

`SystemExit` — исключение, как в s01e10, только его поднимают нарочно.

### `main` возвращает код, процесс завершает одна строка

```python
def main(argv=None):
    ...
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

`argv=None` значит «возьми `sys.argv[1:]`», а тест передаёт свой список.
`python -m toolkit.cli` выполняет нижние строки: `__name__` равен `"__main__"`
(s01e09), и `SystemExit(0)` завершает процесс с кодом 0. При `import` они не
выполняются. `sys.exit` внутри `main` лишил бы тест ответа: вызов кончился бы
исключением, а не числом.

### Ошибку пользователю, а не трассировку

Непойманный отсутствующий файл даст трассировку и код 1: код случайно верный,
а человек видит двадцать строк чужих внутренностей. Перехватывай узко (s01e10):

```python
except OSError as err:
    print(f"toolkit: не читается журнал: {err}", file=sys.stderr)
    return 1
```

При ошибке в stdout не уходит ничего: половина ответов до сбоя выглядит для
следующей программы как полный ответ.

## Проверка: SELENE задаёт вопросы

```
[КАНАЛ 0 · УЗЕЛ НЕ УКАЗАН]
ТРИ ВОПРОСА. ОТВЕЧАЙ ТАК, БУДТО ТЕБЯ ЧИТАЕТ РАСПИСАНИЕ.
```

**1.** «Программа напечатала "ошибка" и завершилась с кодом 0. Что увидит
расписание, которое её запускало?»

<details><summary>Ответ</summary>

Успех. Расписание не читает текст, только код. Ровно так ночной отчёт полгода
был пустым и никого не встревожил.
</details>

**2.** «Без перехвата отсутствующий файл тоже даёт код 1. Зачем тогда `except`?»

<details><summary>Ответ</summary>

Код 1 у непойманного исключения — общий для любой поломки: опечатка в коде даст
тот же 1. Перехват отличает «журнала нет» от «программа сломалась» и говорит
об этом одной строкой, а не трассировкой.
</details>

**3.** «`main` вызывает `sys.exit(0)` в конце. Что сломается?»

<details><summary>Ответ</summary>

Из консоли — ничего. А вызов `main([...])` из теста или из другой программы
вместо числа поднимет `SystemExit`. Код возврата возвращают, а процесс
завершает одна строка под `if __name__ == "__main__"`.
</details>

## Разбор типичных ошибок

1. **Ошибка через `print` без `file=sys.stderr`.** Она уезжает туда же, куда
   результат, и следующая программа примет её за данные.
2. **Код 0 после ошибки.** Расписание увидит успех. Ошибка Рейеса.
3. **`sys.exit` внутри `main` или неперехваченный `SystemExit` от `argparse`.**
   Из консоли работает, из теста — нет: `main` завершает процесс вместо ответа.
4. **Трассировка вместо строки.** Код случайно верный, сообщение — нет.
5. **Разобрать `--low`, но считать с 96.** Аргумент принят и молча забыт.
6. **Печатать по ходу дела.** Второй журнал не прочитался, а ответы первого уже
   в stdout.
7. **`main()` без `if __name__ == "__main__"`.** Программа запускается при
   каждом импорте.
