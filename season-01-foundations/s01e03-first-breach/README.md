## Теория: условие и цикл как поиск

### Условие

```python
>>> pressure = 95.8
>>> if pressure < 96:
...     print("ниже предела")
... elif pressure > 104:
...     print("выше предела")
... else:
...     print("в норме")
...
ниже предела
```

Тело условия выделяется отступом, а не скобками. Отступ в Python — часть
синтаксиса: любой, но одинаковый внутри блока (PEP 8 рекомендует четыре пробела),
и неверный отступ меняет смысл программы.

Сравнения можно сцеплять, как в математике: `96 <= pressure <= 104` означает
`96 <= pressure and pressure <= 104`. Отрицание — `not`, и `not 96 <= x <= 104`
читается как «x вне предела».

### `for`: пройти по всем

```python
>>> for value in [95.8, 100.2, 101.0]:
...     print(value)
...
95.8
100.2
101.0
```

Если нужна не только величина, но и её номер, есть `enumerate`:

`for index, value in enumerate(["a", "b"])` даст пары `0, "a"` и `1, "b"`. Запись
`index, value` раскладывает пару по двум именам; это приём, распаковку разберём
в s01e04.
Номера начинаются с нуля. Первый элемент — нулевой, и это не исключение, а
правило всех последовательностей Python.

### `while`: пока условие верно

```python
>>> position = 1
>>> while position < 4:
...     print(position)
...     position += 1
...
1
2
3
```

`while` нужен, когда шаг цикла не сводится к «следующий элемент»: например, когда
сравниваешь каждый элемент с предыдущим. Цена свободы — забыть `position += 1` и
получить цикл, который не кончается.

### Нашёл — выходи

Поиск обычно не должен идти до конца. `break` прерывает цикл, а `return` внутри
функции прерывает и цикл, и функцию сразу:

```python
def first_negative(numbers):
    for index, number in enumerate(numbers):
        if number < 0:
            return index
    return None
```

Без раннего выхода цикл дойдёт до конца, и последний найденный перезапишет первый.

### `None` — «ничего»

У поиска два исхода: нашли на какой-то позиции или не нашли. Позиция — целое
число, и ноль среди них законный. Значит, «не нашли» не может быть нулём. Не годится
и `-1`: это тоже число, и в Python `values[-1]` — последний элемент, а не ошибка.

Для «ничего» есть отдельное значение — `None`. Проверяют его через `is`:
`result is None`. И главное: `if result:` и `if result is not None:` — **разные вопросы**. Первый
спрашивает «истинно ли значение», и для `0` ответ «нет». Второй спрашивает «есть ли
ответ вообще». Проверка Рейеса задавала первый вопрос, а имела в виду второй.

## Проверка: SELENE задаёт вопросы

```
[КАНАЛ 0 · УЗЕЛ НЕ УКАЗАН]
ПРОЧИТАЛА РЕГЛАМЕНТ. ОН КОРОЧЕ СКРИПТА РЕЙЕСА И ТОЧНЕЕ. ТРИ ВОПРОСА.
```

**1.** «Регламент: 96–104, границы включены. Показание `104.0` — нарушение?»

<details><summary>Ответ</summary>

Нет. «Границы включены» значит `96 <= x <= 104`. Если написать `96 < x < 104`,
показания ровно на границе станут тревогами. Каждый знак сравнения — это решение,
и его принимают по регламенту, а не по привычке.
</details>

**2.** «Почему функция поиска возвращает `None`, а не `-1`, когда ничего нет?»

<details><summary>Ответ</summary>

`-1` — число. Его можно сложить, сравнить, использовать как индекс: `values[-1]`
вернёт последний элемент без всякой ошибки. Неверный ответ пройдёт дальше и
превратится в правдоподобную тревогу. `None` с числом не сложить: ошибка
случится там, где ответ используют без проверки.
</details>

**3.** «Поиск дошёл до конца и запомнил найденное, но без `return` внутри цикла.
Что он вернёт на `[95.0, 100.0, 110.0]`?»

<details><summary>Ответ</summary>

Индекс `2`, последнее нарушение вместо первого. Каждый следующий найденный
перезаписывает предыдущий. Первое — это то, после которого цикл останавливается.
</details>

## Разбор типичных ошибок

1. **`if index:` вместо `if index is not None:`.** Нарушение в первом пакете
   теряется. Ошибка Рейеса, и тест на неё — первый в файле.
2. **`-1` или `False` вместо `None`.** Похоже на ответ и проходит дальше как
   число: `False` равен нулю, `-1` — допустимый индекс.
3. **Цикл с `range(1, len(values))`.** Нулевой элемент не проверяется вовсе. Тот
   же результат, что у Рейеса, другим путём.
4. **`<` вместо `<=`.** Значения ровно на границе становятся тревогами.
5. **Нет раннего выхода.** Поиск возвращает последнее нарушение, а не первое.
6. **`numbers[0]` до проверки длины.** Пустой поток падает с `IndexError`, хотя
   ответ на него простой: пропусков нет.
