# Теория — s01e03

## 1. Отступ как синтаксис

В большинстве языков блок кода ограничивают скобки, а отступ только помогает
читать. В Python отступ и есть граница блока:

```python
if pressure < 96:
    print("ниже предела")
print("проверено")        # выполняется всегда
```

Решение Гвидо ван Россума шло от языка ABC: если программист всё равно делает
отступы, пусть они и будут синтаксисом. Тогда код не может выглядеть иначе, чем
работает. В C из соседнего курса известна обратная ловушка: строка с отступом под
`if` без фигурных скобок выглядит частью условия, но выполняется всегда.

Синтаксис требует только одинакового отступа внутри блока, PEP 8 рекомендует четыре
пробела. Смешивать табуляцию и пробелы Python 3 не даёт:
`TabError`.

> *SELENE, в отладочном канале: «Регламент колонии тоже отделяет пункты отступом.
> Разница в том, что Python его читает».*

## 2. Истинность в условии

`if` принимает любое значение, а не только `True` и `False`. Он спрашивает о
**истинности**, и правила те же, что у `bool` из s01e01: ложны ноль, пустая строка,
пустая последовательность, `None`, `False`.

Это удобно, когда вопрос действительно «пусто ли»:

```python
if values:          # есть ли хоть одно показание
    ...
```

И опасно, когда вопрос другой. Индекс `0`, показание `0.0`, номер пакета `0` —
настоящие значения, но `if` считает их ложью. Правило: **если ноль — допустимый
ответ, проверяй `is None`, а не истинность.**

## 3. `None`: одно на всю программу

`None` — единственный объект своего типа:

```python
>>> type(None)
<class 'NoneType'>
```

Поскольку он один, сравнивать с ним можно на тождество: `x is None`. PEP 8
советует именно так, а не `x == None`. Причина не в скорости: `==` можно
переопределить для своего типа (это s02e03), и тогда `x == None` может ответить
что угодно. `is` переопределить нельзя.

Функция без `return` возвращает `None`. Каркас серии s01e01 писал `return None`
явно, но вернул бы то же самое и без этой строки.

## 4. Почему не `-1`

Во многих языках поиск возвращает `-1`, когда ничего не нашёл. Так устроен
`str.find`:

```python
>>> "O2;N2".find("CO2")
-1
```

В языке, где `-1` не может быть индексом, это работает. В Python отрицательные
индексы считаются с конца: `values[-1]` — последний элемент. Поэтому `-1`, попав
туда, где ждут индекс, не вызовет ошибки, а тихо укажет на последнее показание.
У строк для этого есть второй метод: `str.index` вместо `-1` поднимает ошибку.

Возврат `None` делает ошибку громкой: `values[None]` — `TypeError`.

## 5. `for` в Python — это «для каждого»

В C цикл `for` — это счётчик: начало, условие, шаг. В Python `for` берёт элементы
один за другим из всего, по чему можно пройти:

```python
for value in values:
    ...
```

Счётчик здесь не нужен, и его отсутствие убирает целый класс ошибок: нельзя начать
не с того элемента и нельзя выйти за конец. Если номер всё же нужен, `enumerate`
даёт пары «номер, элемент». Писать `for i in range(len(values))` можно, но это
перевод с C, и именно в нём легко написать `range(1, ...)` и потерять нулевой элемент.

`range(a, b)` выдаёт числа от `a` до `b - 1`: конец не включается. Так
`range(len(values))` — ровно все индексы последовательности.

## 6. `while` и шаг, который надо сделать самому

`while` повторяет тело, пока условие истинно. Всё остальное — твоя забота:

```python
position = 1
while position < len(numbers):
    ...
    position += 1
```

Забыл `position += 1` — цикл никогда не кончится. Поставил шаг перед проверкой —
пропустил элемент. Поэтому `while` берут, когда шаг действительно особенный: когда
сравнивают соседей, идут сразу на два, ждут условия, которое станет верным неизвестно
когда. Для «пройти по всем» есть `for`.

## 7. `break`, `continue` и `else` у цикла

`break` прерывает цикл. `continue` переходит к следующему шагу. У цикла в Python
есть и редкая ветка `else`: она выполняется, если цикл дошёл до конца **без** `break`.

```python
for value in values:
    if value < 0:
        print("нашли")
        break
else:
    print("не нашли")
```

Запись необычна, и многие читатели её не знают: Раймонд Хеттингер говорил, что её
стоило бы назвать `nobreak`. Внутри функции понятнее `return` из цикла и `return
None` после него, как в эталоне серии.

## 8. Поиск: линейный, первый, ранний

Все функции серии — линейный поиск: пройти по порядку и остановиться на первом
подходящем. Если подходящего нет, придётся пройти всё. Другого способа в
неупорядоченных данных нет. Если данные упорядочены, бывают способы быстрее:
двоичный поиск появится в S13, где будет что измерять.

Три решения внутри любого поиска:

| Решение | Ошибка Рейеса и её родственники |
|---|---|
| где начать | `range(1, ...)` теряет первый элемент |
| когда остановиться | без раннего выхода находится последний, а не первый |
| что вернуть, если ничего | `0`, `-1`, `False` похожи на настоящий ответ |

## 9. Пропуск в номерах

`first_gap` сравнивает каждый номер с предыдущим. Если разница больше единицы,
первым пропущен `предыдущий + 1`. Ошибиться можно в том, какой номер считать
ответом: тот, что пришёл после пропуска (`120`), или последний из пропущенных. Тест
серии требует первый пропущенный: именно его ищут в журнале, чтобы понять, что
было потеряно первым.

Функция доверяет тому, что номера возрастают. Что делать с повторами и с
перепутанным порядком, разберём в S6 и S12: там это будет повторная доставка и
сообщения, обогнавшие друг друга.
