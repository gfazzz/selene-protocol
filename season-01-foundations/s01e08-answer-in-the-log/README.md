Ночь тихая. Тамура спит в кресле, накрывшись курткой, табло зелёное.

Ты открываешь сетевой каталог `журналы/`. По файлу на смену, годы смен, сотни

## Чему ты научишься

- Открывать текстовый файл и читать его **построчно**.
- Понимать, что в строке файла есть перевод строки, а в последней его может не быть.
- Указывать кодировку **явно**, а не полагаться на настройки машины.
- Приёму, который дороже синтаксиса: **находка, полученная кодом, повторяется.**

## Теория: чтение файлов

### Открыть, прочитать, закрыть

Файл на диске — последовательность байтов. Чтобы получить из неё строки
Python, файл открывают в текстовом режиме и говорят, в какой кодировке он записан:

```python
with open("data/shift_rejes.log", encoding="utf-8") as log:
    for line in log:
        print(line)
```

`open` возвращает файловый объект. Цикл `for` по нему отдаёт по одной строке за
раз: весь файл в память не читается. `with` закрывает файл, когда блок кончился,
даже если внутри случилась ошибка. Пока это приём записи, а как он устроен,
разберём в s02e05.

### Перевод строки — часть строки

Запусти пример выше, и между строками появятся пустые. Каждая строка файла
приходит **вместе** со своим `'\n'`, а `print` добавляет ещё один. Если печатать
не `line`, а `repr(line)`, на файле из двух строк это видно:

```python
'# 01:00 раз\n'
'0214;O2;20.90;118;0'
```

Последняя строка файла может не кончаться `'\n'` — строкой она от этого быть не
перестаёт. Убирают ровно перевод
строки: `line.rstrip("\n")`.

Файлы, записанные в Windows, кончают строки парой `'\r\n'`. В текстовом режиме
Python сам превращает её в `'\n'`, поэтому код выше годится для обоих.

### `read().split()` и хвост

Можно прочитать файл целиком и разрезать:

```python
>>> текст = "a\nb\n"
>>> текст.split("\n")
['a', 'b', '']
```

После последнего перевода строки остаётся пустая строка: журнал из двух строк
превратился в три. Цикл по файлу этой ошибки не делает.

### Кодировка — не настройка машины

Без `encoding` функция `open` берёт кодировку у системы. На твоей машине это,
скорее всего, UTF-8. На машине Окафор может оказаться другая:

```python
>>> "кто".encode("utf-8")
b'\xd0\xba\xd1\x82\xd0\xbe'
>>> "кто".encode("utf-8").decode("cp1251")
'РєС‚Рѕ'
```

Три буквы — шесть байтов, и в `cp1251` они молча дают шесть других букв. А журнал с
буквой «И» в `cp1251` падает: почему — в вопросе 1. Журнал записан в UTF-8, значит,
и читать его надо в UTF-8: `encoding="utf-8"`.

### Помнить предыдущую строку

Ответ — это пакет `0000`, который пришёл **сразу** после заметки. Значит, при
обходе надо помнить, была ли предыдущая строка заметкой:

```python
предыдущая = None
for строка in строки:
    if предыдущая is not None:
        ...  # здесь видно и строку, и ту, что была перед ней
    предыдущая = строка
```

Прежде чем писать свой обход, спроси себя: где именно это имя должно сбрасываться,
чтобы пакет `0000` через одну строку после заметки ответом не считался.

## Проверка: SELENE задаёт вопросы

```
[КАНАЛ 0 · УЗЕЛ НЕ УКАЗАН]
ПРЕЖДЕ ЧЕМ ЧИТАТЬ НАШУ ПЕРЕПИСКУ — ТРИ ВОПРОСА. ОТВЕТЫ НА НИХ КОРОЧЕ ПЕРЕПИСКИ.
```

**1.** «Окафор запустит твою функцию на машине с `cp1251`. Что будет без `encoding`
с журналом без буквы «И» и с журналом Рейеса, где есть `ЕСЛИ ТЫ ЭХО`?»

<details><summary>Ответ</summary>

Без `encoding` берётся кодировка системы. В `cp1251` почти у каждого байта есть
буква, и журнал без «И» молча станет кашей. У байта `0x98` буквы нет, а «И» в UTF-8
— `d0 98`: журнал с `ЕСЛИ` упадёт с `UnicodeDecodeError`. Код то врёт, то падает;
`encoding="utf-8"` делает результат одинаковым везде.
</details>

**2.** «Файл кончается переводом строки. Сколько строк даст `read().split("\n")` на
журнале из пятисот шестидесяти четырёх строк?»

<details><summary>Ответ</summary>

Пятьсот шестьдесят пять: последняя — пустая. А если журнал не кончается переводом
строки, их будет ровно пятьсот шестьдесят четыре. Код, который считает строки
разрезом, даёт разный ответ на одинаковых по содержанию файлах.
</details>

**3.** «Мои ответы Рейесу можно найти глазами. Чем это хуже, чем найти их кодом?»

<details><summary>Ответ</summary>

Глаза находят один раз и молчат о пропущенном. Функцию можно запустить на сотне
журналов и ещё раз, и любой проверит, как получена находка. Поэтому тест серии сам
собирает журналы и сажает в них ответы: найти надо ровно посаженные.
</details>

## Разбор типичных ошибок

1. **`open(path)` без `encoding`.** На чужой машине портит кириллицу или падает.
   Тест запускает чтение там, где кодировка по умолчанию не UTF-8.
2. **`read().split("\n")`.** Лишняя пустая строка в конце и пустые строки внутри.
3. **Убрать перевод строки срезом `line[:-1]`.** Последняя строка файла без `'\n'`
   теряет свой последний символ. `rstrip("\n")` убирает только то, что есть.
4. **Не сбросить «предыдущую заметку».** Тогда ответом считается любой пакет `0000`
   после заметки, а не только следующая строка.
5. **Вернуть заметку вместе с `'# '`** или ответ вместе со всей строкой пакета.
6. **Вписать найденные ответы в код.** Журнал Рейеса пройдёт, любой другой — нет.
