# Теория — s01e08

## 1. `def` выполняется

В C функция — часть текста программы, она существует до запуска. В Python `def` —
инструкция, такая же, как присваивание. Пока интерпретатор до неё не дошёл,
функции нет; когда дошёл — создан объект, и имя привязано к нему.

```python
>>> def show():
...     return "сводка"
...
>>> report = show
>>> report()
'сводка'
>>> report is show
True
```

Два имени — одна функция, как в s01e05 два имени — один список. Функцию можно
передать аргументом и вернуть из другой функции. Это пригодится в S2.

> *SELENE, в отладочном канале: «Рейес считал, что функция — это кнопка. Кнопка
> не помнит, сколько раз её нажимали. Функция Рейеса помнила».*

## 2. Когда вычисляется умолчание

При выполнении `def`, один раз. Это видно на любом умолчании, которое зависит от
момента вычисления:

```python
>>> import time
>>> def stamp(t=time.time()):
...     return t
...
>>> stamp() == stamp()
True
```

Время «застыло» в момент `def`. (`import` здесь — приём, модули разберём в s01e09.)
Значения хранятся в функции, в атрибуте `__defaults__`, и их можно посмотреть:

```python
>>> def collect(found=[]):
...     found.append(1)
...     return found
...
>>> collect(), collect()
([1, 1], [1, 1])
>>> collect.__defaults__
([1, 1],)
```

Оба вызова вернули **один и тот же** список. Поэтому кортеж результатов показывает
его дважды в последнем состоянии.

## 3. Почему так устроено

Другие языки решили иначе. В JavaScript и Ruby выражение умолчания вычисляется при
каждом вызове, и список-умолчание там безопасен. Python выбрал однократное
вычисление по двум причинам. Первая — простота модели: `def` вычисляет всё, что
написано в его строке, сразу, как любая другая инструкция. Вторая — цена: дорогое
выражение в умолчании не повторяется на каждом вызове.

Расплата — правило, которое нужно помнить: **изменяемое умолчание общее для всех
вызовов.** Его знает каждый, кто писал на Python больше месяца. Обычно потому,
что однажды на нём попался.

## 4. Маркер «не передано»

Стандартный приём — `None` в подписи и новый объект внутри:

```python
def collect_alerts(readings, low, high, found=None):
    if found is None:
        found = []
```

Почему `is`, а не `==`: `None` существует в одном экземпляре, и вопрос «это он?» —
вопрос о тождестве (s01e05). Почему не `found or []`: `or` спрашивает об истинности,
а пустой список ложен.

```python
>>> def f(found=None):
...     found = found or []
...     return found
...
>>> mine = []
>>> f(mine) is mine
False
```

Если `None` — законное значение аргумента и путать его с «не передано» нельзя,
заводят собственный маркер: `_MISSING = object()`. Новый `object()` не равен ничему,
кроме себя, и случайно передать его невозможно.

## 5. Какие умолчания безопасны

Неизменяемые: числа, строки, `None`, `True`/`False`, кортежи из неизменяемого.
Их нельзя испортить, поэтому общий объект никому не мешает:

```python
>>> def add(n, total=0):
...     total = total + n
...     return total
...
>>> add(1), add(1)
(1, 1)
```

`total = total + n` не меняет число `0`, а привязывает локальное имя к новому
числу. Опасны списки, словари, множества: у них есть `append`, `[key] = …`, `add`.

## 6. Области видимости

Python ищет имя в четырёх местах по порядку: **L**ocal (внутри функции),
**E**nclosing (внутри объемлющей функции, S2), **G**lobal (модуль), **B**uilt-in
(`len`, `print`). Правило LEGB.

Ловушка: если имени присваивают где-нибудь внутри функции, оно локальное во всей
функции, даже до присваивания.

```python
>>> x = 10
>>> def bump():
...     x = x + 1
...     return x
...
>>> bump()
UnboundLocalError: cannot access local variable 'x' where it is not associated with a value
```

Есть `global x`, который разрешает менять глобальное имя. В этом курсе он не нужен:
функция, которая меняет глобальное состояние, — та же функция Рейеса, только память
у неё в другом месте.

## 7. Изменить аргумент — это договорённость

`collect_alerts(readings, low, high, found)` меняет переданный список. Это не
нарушение правила «функция не помнит», а явный договор: вызывающий **сам** дал
список и сам решил, что в него копить. Так удобно собирать тревоги по частям, не
склеивая потом результаты. Тест серии проверяет именно это: тревоги по частям в
одном `found` равны тревогам по всему списку.

Разница между функцией Рейеса и этой — в том, кто владеет накопителем. У Рейеса —
функция, тайно. Здесь — вызывающий, явно.

## 8. Позиционные и именованные

Порядок в подписи: сначала обязательные, потом с умолчаниями. Наоборот нельзя:
`def f(a=1, b)` — `SyntaxError`. При вызове позиционные идут перед именованными.

Звёздочка в подписи делает аргументы после неё **только именованными**:

```python
def count_alerts(readings, low, high, *, counts=None): ...
```

Тогда `count_alerts(r, 96, 104, {})` — ошибка, а `count_alerts(r, 96, 104,
counts={})` — нет. Для накопителя это хорошая защита от путаницы, но в этой серии
договор позволяет передавать его и по позиции.

## 9. f-строки

`f"{prefix} {node} #{sequence}"` — строка, в которой выражения в фигурных скобках
заменены их значениями. `f"{101.3}"` даёт `'101.3'`, `f"{100.0}"` — `'100.0'`:
число превращается в строку так же, как `str()`. Формат чисел (знаки после точки,
выравнивание) разберём, когда понадобятся отчёты.
